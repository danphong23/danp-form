# Product Definition

**Status: Normative**

## Simple description

DANP Form lets a person or AI reshape an existing template mesh by manipulating a sparse network of control lines that are backed by real Source topology.

The user creates controls once, then works mainly with ordinary selection and G/R/S. Effective enabled control edges divide the surface into topology-derived patches. When a control changes, only patches incident to that control are eligible to deform. Their **current dense shape** is retained as the operation baseline, and a smooth displacement is propagated from control targets into the patch according to the proportional setting.

The result is written directly to the Source Mesh without changing topology.

## Product promise

A small number of predictable control actions should be enough to make broad and local shape edits while retaining the useful form already present in the template/current mesh.

## Core workflow

```text
1 Source Edit Mode: select real edges/vertices → Make Control
2 DANP Form derives patches from enabled control edges
3 Control Proxy: select node/edge/control
4 G / R / S or explicit numeric target
5 Resolve selected node/strip/span/loop geometry into Source targets; other enabled vertices hold
6 Propagate those targets over adjacent patches
7 Write preview from immutable Operation Rest
8 Commit → Source becomes the new current shape
```

## Core does not know semantics

`front`, `side`, `arm`, `leg`, `head`, `car`, or anatomical meaning are not core concepts. A control is just source topology plus interaction metadata.

## Non-goals of core

Core does not require:

- automatic image segmentation;
- camera calibration;
- AI 3D reconstruction;
- semantic anatomy recognition;
- a permanent deformation modifier;
- a rig/armature replacement;
- a specific numerical solver family.

Reference fitting may be added later only as a **target producer** for the same controls.

Enabled unselected controls hold their coordinates. DANP Form Hide releases a line or
portion from both constraints and patch cuts; Reveal restores it on the current mesh.
This replaces a separate deactivate/nesting system. See leg-control-examples.md.

# Terminology

**Status: Normative**

- **Source Mesh** — the real editable Blender mesh. Its current coordinates are the final geometric truth.
- **Template** — a Source intended for reuse. It may have an optional original snapshot for reset/compare.
- **Control Definition** — source-owned metadata identifying source vertices/edges that form a control.
- **Control Component** — one connected point/chain/loop/branch inside a logical control.
- **Control Proxy** — rebuildable points/edges shown to the user/agent for selection and transforms.
- **Proxy Knot** — an editable proxy vertex bound to an actual source control vertex.
- **Proxy Span** — a proxy edge that represents an ordered run of one or more source control edges between two proxy knots.
- **Enabled Control Network** — effective Source control edges/vertices after applying canonical hide masks; called active in older drafts.
- **DANP Form-hidden Control Geometry** — stored Source-backed definitions temporarily released from constraints/cuts, allowed to follow mesh deformation.
- **Reveal** — resample current Source positions and restore effective roles; not reset or refine.
- **Patch** — connected component of source faces after adjacency across effective enabled control edges is removed.
- **Operation Rest (`P0`)** — snapshot of current Source coordinates at operation start.
- **Control Target (`Q`)** — target position assigned to a source control vertex for the current operation.
- **Dense Target Set** — one moved or stationary target per enabled Source control vertex in scope; Blender Proportional Editing may move vertices beyond the explicit selection.
- **Affected Patch Set** — patches incident to moving target geometry for the current operation.
- **Captured Patch Scope** — patches incident to selection at invoke; bounds snapshot/writeback and prior-preview cleanup even when current affected scope shrinks.
- **Proportional** — user-controlled attenuation of patch displacement as Source-local rest-edge distance from moving targets grows.
- **Original Snapshot** — optional historical template state used for reset/compare only.

# User Workflows

**Status: Normative**

## Prepare and edit

Register Source, select Source topology, Make Control and repeat. Patch authoring is
automatic. On the proxy, select a point, strip, span/edge or loop; use G/R/S, choose
proportional, then confirm/cancel. The initial selection starts Blender's native
transform. DANP compares the whole Controller against its pre-transform pose, so
every proxy vertex that actually moved becomes an exact Source target, including
unselected vertices affected by Blender Proportional Editing. Enabled control
vertices that did not move remain fixed. Named control selection is optional.

## Let a contour follow the mesh

Use DANP Form Hide Control on a whole line or selected portion. It temporarily stops
holding mesh and cutting patches. Recompute actual connectivity; patches may merge.
Transform remaining enabled controls. Hidden geometry follows affected patch motion
under proportional. Reveal samples that contour at the new Source positions.

At intersections, other enabled edges may still hold a shared endpoint. Hide endpoint
nodes too if they should be released. No parenting between control definitions or
nested-control feature is required; the controller object itself is a child of Source.
Ordinary object/collection display hiding does not substitute for this command.

Hide whole edge-backed lines uses edge intent to preserve junctions on retained lines.
Node-mode Hide also disables incident edges. Selecting a hidden definition does not
reveal it; use Reveal separately.

## Repeat, rebuild and undo

Each committed result becomes the next Operation Rest. Hide/reveal itself deforms
nothing and is undoable separately. Delete/rebuild proxy without losing Source shape,
definitions or hide masks. Reveal does not reset original positions.

See leg-control-examples.md for the two-loop/longitudinal-line workflow.

## Inspect patches and fit references

Toggle Show Patches to inspect regions without changing deformation behavior. Hide
controls to change actual cuts/constraints; hiding the overlay does not do that.
Create normal Source-backed contours along front/side reference views, then adjust
points/spans/loops with proportional. Human or agent chooses targets through the
same operations; automatic silhouette extraction/calibration is a future extension.

# Core Invariants

**Status: Normative**

1. **Source is truth.** Completed deformation exists as ordinary Source coordinates.
2. **Proxy is input.** Deleting the proxy must not revert the Source.
3. **Current shape is rest.** Every operation captures the current committed Source as `P0`.
4. **One operation, one rest state.** Preview N never becomes the rest state for preview N+1.
5. **No original-template pull.** Historical positions are not silently blended into normal deformation.
6. **No-op means no geometry change.** If all resolved control targets equal `P0`, the operation must return `P0` exactly within storage round-trip.
7. **Patches come from topology.** An open control chain divides a surface only if removing adjacency across its source edges actually disconnects faces.
8. **Enabled unselected geometry holds.** Every enabled Source control vertex outside explicit resolved node/span/loop selection stays at P0, even when omitted from a sparse proxy. At a shared vertex, a selected target wins.
9. **No write outside scope.** Vertices outside captured incident-patch scope are untouched. Preview cleanup resets prior writes within that scope before applying current output.
10. **Proportional is a patch-propagation control.** It is not silently applied again during sparse target expansion.
11. **Topology is preserved by deformation.** G/R/S deformation changes coordinates, not Source connectivity.
12. **Human and AI share the path.** They produce the same canonical control targets and call the same deformation operation.
13. **Reference fitting is downstream of target generation only.** It never gets its own mesh-writing solver.
14. **Normal cancel is exact.** With unchanged identity/topology, cancel restores Source and Proxy to operation-start state. Topology/deletion errors follow explicit recovery limits, never stale index writes.
15. **Commit is cumulative modeling.** The committed result becomes the next operation's rest shape.
16. **Hide releases, Reveal adopts.** DANP Form-hidden geometry neither cuts nor constrains; Reveal samples the current Source without restoring old positions.
17. **Partial state is geometry-backed.** Whole/partial hide masks are canonical Source IDs, not per-logical-membership state.
18. **Grouping is not geometry.** Identical effective network, targets and settings yield equivalent results regardless of names/groups.
19. **Preview can return to rest.** Returning targets to P0 or shrinking influence clears earlier preview displacement instead of leaving residual deformation.

# Control Model

**Status: Normative — clarified with the product owner on 2026-09-18**

## Geometry, not named roles

Controls are real Source vertices/edges with persistent definitions. Points, chains,
loops, disconnected sets and intersecting networks are interaction shapes. Names and
groups are selection conveniences, not front/side/anatomy roles or independently
weighted deformation components. The same effective network and targets must produce
the same result regardless of how definitions are named/grouped.

One rebuildable proxy per Source exposes geometry for selection and transforms.
Create/remove structure through DANP Form commands, not arbitrary proxy topology edits.

## Enabled control

An enabled control vertex changes only through explicit selection on the control.
Every enabled vertex outside the resolved selection stays exactly at Operation Rest.
It cannot be dragged along by another selected control or patch interpolation.
Enabled edges contribute to topology cuts even when their endpoints are selected.

A selected proxy span represents its entire stored Source span: those dense vertices
are selected geometry too. A knot-only selection does not select neighboring spans.

## DANP Form Hide and Reveal

One user-facing state: enabled or DANP Form-hidden. Hide releases hidden geometry from
both stationary constraints and topology cuts, without deleting Source elements or
definitions. Reveal restores those roles at current Source positions, never old ones.

Hide/reveal works on a whole definition or selected points/edges/spans. Hidden vertices
follow ordinary mesh deformation inside affected regions; they are not guaranteed to
move, because proportional and other enabled constraints still apply.

No control parenting, nested patch ownership or separate deactivate feature is needed.
Object/collection hiding only changes display; it is not DANP Form Hide Control.
Proxy H/Alt-H may be bound to DANP Form commands when the tool owns the context.

## Canonical masks and shared endpoints

Store hidden Source vertex IDs and edge IDs once per Source network, not per logical
membership. Hiding an overlapping edge must not leave another invisible membership
constraining it. Commands use Source IDs independent of proxy resolution.

- Hide nodes: mark the represented vertices hidden; their incident control edges become ineffective.
- Hide edges/spans: mark represented edges hidden. Endpoints remain enabled when supported by another effective edge or an unhidden standalone point/set control.
- Hide whole edge-backed definition/loop: hide its represented edges, not all endpoint nodes. This preserves junctions supported by other enabled lines. For standalone point/set components, hide their represented nodes. Mixed components use the union of these intents.
- In edge mode, selecting an edge does not turn its endpoint selection flags into extra Hide Nodes requests. Mixed explicit node/span requests are a union; only explicit node intent hides nodes. The same rule applies to numeric/agent commands.
- Effective edge: a defined control edge, not edge-hidden, with neither endpoint node-hidden.
- Effective vertex: not node-hidden and supported by an effective edge or an unhidden standalone point/set control. Vertices supported only by hidden edges are released.
- Reveal nodes clears their node masks; independently edge-hidden edges stay hidden.
- Reveal edges/spans clears their edge masks and endpoint node masks to make requested geometry usable.
- Reveal whole definition clears its represented edge/node masks; Reveal All clears all masks.

Recompute the effective network/display after every state change. Shared endpoints
still supported by enabled geometry remain available. To release them too, hide nodes.

Node masks are global: hiding a junction node releases all incident lines at that node.
Revealing an edge clears endpoint node masks, so other edges disabled only by those
node masks can become effective too. Independently edge-hidden branches stay hidden.
This is shared Source geometry, not per-control ownership; UI preview and agent results
should report the resulting effective geometry rather than promise an isolated change.

Hide/reveal is idempotent. Repeating the same command without changing masks creates
no extra state revision or meaningful undo step. It never stores a pre-hide shape.

New definitions default enabled only where canonical masks already allow them: creating
an overlapping definition must not silently reveal previously hidden geometry. Remove
definitions without deleting Source topology; retain masks for elements still defined
elsewhere and prune masks for elements no longer in the defined network.

## Junction target priority

There is one position per Source vertex. A selected target wins over an unselected
membership at that same point. Other vertices on the unselected line remain fixed.
Two incompatible selected targets return TARGET_CONFLICT; do not average them.
Hiding one branch does not release a junction still supported by an enabled branch.

## State lifecycle

Hide/reveal is an undoable structural operation. Invalidate patch/constraint/distance
caches and resync proxy without deforming Source. Persist masks through save/load and
rebuild. Freeze the effective network during deformation: finish/cancel before hiding
or revealing. Stale requests must not reuse old patch scope.

# Patch Model and Influence Boundary

**Status: Normative**

Derive patches as Source face-graph components after removing adjacency across effective
enabled control edges. Hidden edges do not cut. Names/groups have no geometric effect.

An interior open chain splits only if connectivity actually disconnects. One longitudinal
line on a cylinder may leave one patch because faces can route around the other side.
Never promise hiding a line always merges exactly two patches.

## Operation scope and constraints

Resolve every Source control vertex that actually moved, including vertices moved by
Blender Proportional Editing. Include every patch
incident to moving Source geometry, including all sides of separators and junctions.
Unrelated patches are excluded; proportional radius cannot expand that set.

Capture all patches incident to resolved selection at operation start as potential scope.
Per-update affected scope may shrink when targets become zero; operation-semantics.md
requires resetting earlier preview writes to P0. Patches outside captured scope are
never written, including during cleanup.

Moved enabled vertices hit their targets. Every other enabled control vertex stays
at P0. Hidden vertices are ordinary mesh vertices, not anchors: they can follow
deformation inside this scope and proportional radius.

## Patch graphs and shared vertices

A control vertex propagates to a set of graph-connected vertices inside incident
patches, subject to proportional and hard constraints. Paths follow member-face
edges; they may branch. Do not assign one exclusive vertex chain to each control
vertex or infer horizontal/vertical/anatomical directions from control names.

Each enabled control vertex supplies an exact boundary position. Moved vertices
have displacement Q-P0; unchanged vertices have zero displacement. Free patch
vertices interpolate those per-vertex constraints using rest-edge geometry.
Logical control definitions do not change the solve. A coherent whole-control
transform can extend through a patch without a fixed boundary; a nonuniform
transform uses the same per-vertex interpolation as any other edit.

Patch visualization visibility is display-only. All patches remain available to
scope/solve regardless of overlay toggles; DANP Form control Hide changes actual
partition as described below.

Use edges of member faces to build each patch graph, not shortcuts through other patches
in a global induced vertex graph. Boundary vertices can belong to multiple patches.
Shared enabled vertices have the same hard moving/fixed target in all incident solves.
Validate agreement before writeback; last-write order must not resolve conflicts.
Vertices belonging only to patches outside captured scope are never written.

The prototype rejects non-manifold/vertex-only connections rather than merging
incompatible free-vertex results. Manifold surfaces with boundary are the correctness
baseline. A deformation with no incident faces/patch returns NO_AFFECTED_PATCH before
writing; loose point/edge controls are not an alternate direct-mesh edit path.

## Hide/reveal

Recompute connectivity after hiding any control portion. If patches merge, subsequent
operations use the new patch scope. Hiding itself changes no Source coordinates.
Reveal resamples current Source and restores cuts; it does not revert shape or replay
previous operations. Partial hiding leaves retained enabled portions as cuts/constraints.

Freeze the enabled network for each deformation. Network/visibility revision changes
invalidate the transaction; do not continue with old cached patches.

# Selection and Control Targets

**Status: Normative**

Select control geometry as on a mesh: a vertex, a strip of vertices, an edge/span,
a loop, or multiple elements. A named definition is only a selection shortcut.

## Resolve selection

1. Snapshot the enabled network and current Source P0.
2. Node selection resolves to those Source vertices only.
3. Selected edges/spans select all represented enabled Source vertices in those spans.
4. Loop/whole-control selection is the union of its enabled nodes/spans. Hidden segments stay excluded; selection does not silently reveal them.
5. Deduplicate by Source ID. Selected span endpoints count as selected even without endpoint knot flags. Unselected neighboring spans do not become selected at operation start.
6. The initial selection starts Blender's native transform. During each preview sample,
   compare every Controller vertex with its pre-transform pose. Every ID whose
   coordinate changed is an exact target, including unselected vertices moved by
   Blender Proportional Editing. Enabled control vertices that did not change are
   stationary for that sample.

Hidden geometry contributes neither targets nor stationary constraints. Explicit edit
requests for hidden elements return CONTROL_HIDDEN; reveal in a separate command.

## G/R/S targets

From the operation-start transform, pivot and orientation, Blender produces the live
Controller coordinates. DANP resolves targets from the changed-coordinate set:

```text
Q[i] = Controller[i] for every moved Controller vertex
Q[i] = P0[i]         for every enabled Controller vertex that did not move
```

A selected coarse edge transforms the existing dense curve, not a reconstructed chord.

Targets are Source-local. Convert world/orientation operations through the captured
object transform; do not assume local/world axes match. Reject singular/non-finite
transforms. Freeze the frame so equivalent human/agent targets have the same meaning.

## Knot-only selection, including sparse mode

Without Blender Proportional Editing, only the selected knot's bound vertex moves.
With Blender Proportional Editing, omitted enabled vertices may also move; DANP
detects their changed coordinates and treats them as targets. To move more of a
line deliberately, select its strip/span/loop. To let a line follow mesh
deformation, hide it first.

## Numeric/agent parity and conflicts

Explicit targets obey the same selection and Source IDs. Node-only calls do not infer
a transform for intermediate vertices. Rotate/scale a selected span using a transform
call, or supply targets for every selected dense vertex. Span coverage is explicit
selection, not proportional falloff.

At a junction, moved targets win over stationary membership. Incompatible moved
targets return TARGET_CONFLICT regardless of order. No generated moving target is
allowed outside the current Controller mapping.

Validate target count, finite values, Source-scoped IDs and selection membership before
writes. Do not discard unknown IDs/malformed partial payloads silently. Validate explicit
hidden-element requests before filtering: whole-definition selection can skip hidden
portions, but explicit hidden nodes/spans return CONTROL_HIDDEN.

A junction included in any selected span is selected; neighboring spans remain unselected
except that endpoint. Names never decide priority. Targets do not need front/side modes.

## No-op

All selected Q equal P0 means unchanged Source. Such targets are not nonzero influence
sources. Numerical comparison tolerance is a prototype parameter, not permission to
move unselected enabled control vertices.

After an earlier nonzero preview, no-op must restore previous writes to P0. Early-out
skips solving, not cleanup; see operation-semantics.md.

# Proportional Semantics

**Status: Normative role and placement; exact default/profile set remains open**

Within already affected patches, proportional governs how moved control vertices
spreads into mesh interiors. It does not select patches, release enabled controls,
or define new control targets. Current patch shape is the deformation baseline.

The additive candidate computes U then applies the user's profile once:

```text
P1(v) = P0(v) + A(v) * U(v)
```

For finite radius R > 0, use shortest rest-edge metric distance inside
the patch from nonzero moved targets:

```text
x(v) = clamp(1 - d_move(v)/R, 0, 1)
A(v) = profile(x(v))
```

Whole Patch uses A=1 within affected scope, not across enabled cuts. Enabled stationary
vertices remain exactly P0 regardless of radius. Moved targets remain exactly Q.
Hidden vertices are attenuated like ordinary mesh vertices and may remain unchanged
outside radius. Zero/negative/non-finite radius requests must be rejected or represented
as an explicit separate mode; do not divide by zero.

Initial candidate profiles are dimensionless, with profile(0)=0, profile(1)=1 and range
[0,1]. Phase 4 compares LINEAR x, SMOOTH x*x*(3-2*x), and a uniform attenuation
candidate: A=1 for d_move < R, A=0 for d_move >= R. Uniform finite-radius attenuation
has a discontinuity at R; review its visual behavior, not assume it is the default.
Whole Patch uses constant A=1 without a radius cutoff. These describe attenuation,
not identical interior displacement or release of fixed controls. Shipping set and
default remain open. Radius/distances use Source-local Operation Rest units. A
world-space UI must convert or document its metric, particularly for nonuniform object
scale; do not silently mix units.

Radius/profile changes recompute from P0 and clear old motion outside new influence.
No nonzero targets means P0 output; do not compute distances to an empty moving set.
Moved control vertices still receive Q.

No fixed midpoint motion or mandatory affine deformation follows from choosing a
profile. Prototype comparisons must use identical targets/constraints while changing
profile/radius. Numerical influence method and quality require evidence.

Blender's native Proportional Editing may move enabled unselected Controller
vertices. DANP accepts those coordinates as exact targets by comparing the whole
proxy with its pre-transform pose. DANP's own Radius/profile then controls how the
resulting moved targets influence free Source vertices inside the affected patches;
it does not override Blender's proxy falloff. Sparse representation adds no second
user proportional.

# Patch Interpolation Prototype

**Status: Current solver; required behavior comes from core contracts**

## Product requirements

Inputs are immutable current patch P0, actual patch topology, the Controller vertices
that actually moved, unchanged enabled control vertices, and proportional settings. Hidden geometry is
ordinary Source geometry. Names/logical grouping must not affect the result.

Keep current patch form as the geometric starting point. Generate its deformation from
control movement and the user proportional setting; never reconstruct a patch solely
from sparse endpoint positions or pull toward the historical template. Extra detail
preservation is not mandated; a user can add controls around a feature to edit it separately.

Hard targets: moved vertices equal Q; unchanged enabled vertices equal P0. No-op
returns P0 and clears old preview motion. New deformation stays in currently affected
patches; cleanup stays in captured scope. These rules hold for every method.

No required formula says a patch midpoint moves half as far as a boundary. Whole Patch
and finite radius/profile may produce different interior responses. Inspect leg examples
in product/leg-control-examples.md before interpreting interpolation results.

## Current interpolation

For every enabled control vertex in an affected patch, take its measured Controller
displacement `D[i] = Q[i] - P0[i]`; an unchanged vertex has `D[i] = 0`. These are exact
constraints. For a free vertex, solve a weighted discrete Laplace equation on the
patch's Source edges:

```text
sum over neighbors j: (D[v] - D[j]) / length_P0(v,j) = 0
P1[v] = P0[v] + A[v] * D[v]
```

This spreads local Blender Proportional motion along the boundary smoothly into the
patch without fitting one transform to a named control. In a straight strip, edge
resistance follows its original length, retaining the spacing ratios of intermediate
rings. A free component unreachable from any constraint retains P0. With no fixed
boundary and a coherent whole-control G/R/S, a fitted transform can extend through
the patch; nonuniform targets use the constrained solve.

`A` is 1 for Whole Patch (`Radius = 0`), or the chosen profile of Source-local
rest-edge distance for finite radius. It never weakens hard control targets.
Every preview starts from immutable P0, not the previous preview. Build and
validate the complete output before writeback; copy hard targets and unchanged
control positions exactly and reject conflicting shared-patch results.

The solver minimizes edge displacement differences. It does not guarantee
volume preservation or prevent face inversion under extreme edits. More
geometric controls can constrain important features when needed.

## Required observations

- No targets change: exact unchanged geometry, with no relaxation.
- One boundary moves: target exact, other enabled controls fixed; inspect how each chosen profile/radius changes interior motion.
- One knot moves: no other enabled Source control vertex moves, even if proxy is sparse.
- One span or both loops scale: selected dense vertices hit T(P0); enabled longitudinal lines hold; hidden ones follow allowed patch motion.
- Rotate a span: selected Source line transforms exactly; inspect interior shear/smoothness without assuming exact rigid rotation of the whole patch.
- Repeat edits: next operation uses the last committed shape as P0.
- Hide/reveal: topology scope changes, hidden paths follow mesh and reappear at current positions.

## Evidence and limits

Measure smoothness, rotations, irregular topology, sampling-density sensitivity and
proportional response. Adding P0 does not prove every detail is perfectly preserved.
Choose the smallest improvement for a reproduced failure; no mandatory ARAP/harmonic,
SVD or multi-stage backend follows from product definition. Prototype engineering
parameters can change without redefining selection, hide state or hard constraints.

# Sparse Controls and Simplification

**Status: Normative behavior; optional after exact controls are validated**

Simplify/refine changes handles only, not Source topology, enabled control geometry,
hidden masks or stationary constraints. Knots bind to real Source vertices; spans
store actual dense Source paths.

Selecting a span selects its represented enabled vertices: G/R/S applies T(P0[i]).
Selecting a knot selects only its bound vertex. Omitted enabled vertices remain fixed.
The earlier knot-only linear displacement expansion is superseded. Select spans for
broad changes or hide geometry to release it.

Split spans at visibility transitions and junctions: no editable span may cross a
hidden gap. Dense control overlays may show the actual curve under coarse straight edges.
Mandatory knots include endpoints, junctions and enabled/hidden transitions; choosing
other knots is a later engineering heuristic.

Refine exposes existing handles, not hidden controls. It must not clear masks or create
Source vertices. Simplify/refine alone deforms nothing. Preserve logical selection
where unambiguous; reveal resamples current Source, including omitted vertices.

# Operation Semantics

**Status: Normative**

## Capture

Validate editable Source, mapping and supported topology; sync proxy from current Source.
Resolve selection once and freeze enabled network, selected Source IDs, pivot/orientation,
topology fingerprint and network/proxy generations. One transaction owns a Source.

For native Controller Edit `G/R/S`, capture happens in the DANP macro's Begin step,
before Blender's transform operator receives its first mouse delta. Blender's native
transform remains responsible for axis locks, numeric input, snapping and modal input;
DANP only observes the absolute Controller pose against the captured rest and writes
the Source preview. The macro's Finish step is the only native Confirm path.

Capture immutable P0 for every vertex in potential operation scope: all patches incident
to resolved selection, even when the initial transform is zero. Capture proxy start state
and enabled hard constraints. Never change coordinates outside this captured scope.

## Preview updates

Targets are absolute relative to operation start, not incremental transforms of preview.
From P0, resolve selected Q, fix other enabled vertices, identify nonzero targets and
compute affected patch output. Initialize the entire captured-scope output buffer to
P0 before inserting this update's results; validate before writing. This resets earlier
preview displacement when targets return to P0, radius shrinks or affected scope shrinks.

```text
P0 + target_1/settings_1 → preview_1
P0 + target_2/settings_2 → preview_2
P0 + unchanged targets  → P0, including every earlier previewed vertex
```

Resetting prior preview writes is cleanup within captured scope, not permission to deform
unrelated patches. Identity updates return NO_CHANGE and can keep a transaction open;
early-out may skip solving but must not skip resetting previous preview writes.

## Confirm/cancel

Confirm validates generations, targets and finite output, writes the accepted method,
syncs proxy and records one logical undo operation. Preview/final may refine free vertices
but share hard targets, masks, scope and P0. Next operation uses the committed result.

With unchanged topology/identity, cancel restores exact P0/proxy start state, releases
ownership and creates no meaningful undo entry. Confirm with a result identical to start
returns NO_CHANGE instead of claiming an edit. Update/commit/cancel after closure returns
OPERATION_CLOSED without writes.

The native timer is cancellation-only for macro-managed sessions. It must never commit a
non-zero preview merely because Blender's operator list is temporarily empty while the
user pauses the mouse. A Controller pose restored to its captured C0 is treated as Cancel;
native Confirm is handled exclusively by the macro Finish step.

## Structural state/ownership

Hide/reveal, definition edits, rebuild and simplify/refine are separate operations with
zero deformation and their own undo semantics. Reject them during a transform with
OPERATION_BUSY: finish/cancel first. Freeze selection/network/proxy representation during
the transaction. Reject second ownership of the same Source; unexpected revision changes
invalidate the operation. Native proxy transforms bypassing DANP Form cannot commit mesh
deformation; resync from Source before the next valid operation.

## External edits and recovery

Coordinate-only Source edits outside transactions are valid; resample at the next boundary.
External coordinates/object-transform or mode-ownership changes during a transaction
invalidate it before another write; do not absorb them into P0. This ownership validation
is operation-local, not continuous scene polling.

Handled numerical errors with unchanged topology restore P0/proxy and cancel. If Source
identity/topology changes, stop stale-index writes. Restore only coordinates with proven
identity; a coordinate snapshot is not a topology rollback. Report TOPOLOGY_CHANGED or
OPERATION_STALE and block continuation. Source deletion and unhandled Blender crashes
cannot promise exact rollback; normal Blender recovery applies. No operation snapshot
becomes persistent authoritative template data.

# System Overview

**Status: Normative architecture**

```text
           Source Mesh
  geometry + source-owned control definitions
          ▲                 │
          │ write           │ build/sync
          │                 ▼
  Deformation Operation ← Control Proxy
          ▲                 ▲
          │                 │
   canonical targets     User / AI
          ▲
          │
 Future reference fitting (target producer only)
```

## Persistent truth

Source-owned:

- current mesh coordinates/topology;
- persistent element IDs;
- logical control definitions;
- canonical hidden vertex/edge masks;
- Source/template UUID;
- minimal settings that must survive save/reload.

## Rebuildable state

- Control Proxy geometry;
- effective network/patch partition cache derived from persistent hide masks;
- topology distance caches;
- interpolation work buffers;
- overlays/diagnostics.

## Core services

Conceptual responsibilities:

- Context resolution — Source ↔ Proxy ↔ template identity.
- Persistent IDs — stable source element references.
- Control repository — create/remove definitions and whole/partial hide masks; derive enabled Source geometry.
- Proxy builder/sync — rebuild interaction geometry from Source.
- Patch service — derive face components from effective enabled control cuts.
- Target builder — selection/G/R/S/agent input → Dense Target Set.
- Deformation operation — capture P0, interpolate, preview, commit/cancel.
- Agent facade — same primitive actions without mouse simulation.

No service boundary requires a specific numerical interpolation family.

# Mapping, Persistent IDs, and Source/Proxy Sync

**Status: Normative**

## Persistent identity

Do not use Blender element index as long-term control identity. Assign integer attributes on Source points/edges (and optionally faces) and use monotonic counters per Source.

Suggested names:

```text
.dan_form_vid
.dan_form_eid
.dan_form_fid   # optional
```

## Proxy binding

Every proxy knot stores the Source vertex ID it represents. Every proxy span identifies one control component and the ordered Source vertex/edge run it represents.

The controller object is parented directly to Source with matching Source-local
coordinate frame and no extra object offset. Source object transforms carry it once;
they are not control-edit operations. Proxy wires are 3D vertex/edge geometry with
no faces, even when users draw/select contours from front/side views. Exact proxy
is implemented first; sparse spans remain optional future representation.

## Sync boundaries

Before transform, hide/reveal, simplify/refine, agent target query, or explicit validation:

1. resolve Source/Proxy pair;
2. validate Source topology generation/fingerprint;
3. validate persistent IDs/control membership;
4. rebuild proxy if missing/corrupt but definitions are valid;
5. copy current Source positions to proxy knots;
6. for deformation only, resolve selection and capture P0/potential incident-patch scope.

After commit, resync proxy from the newly committed Source.

## Coordinate changes outside DANP Form

Safe when topology remains valid. Visible proxy coordinates must refresh from Source
after external coordinate edits, including Source Edit Mode; implement a lightweight
dirty/event refresh in a safe context and measure it in phase 2. Command boundaries
still revalidate and sample current Source. Source always wins outside an active DAN
Form operation. Do not use continuous bidirectional coordinate writes or numerical
deformation in depsgraph handlers.

In phase 4 an owned controller-edit transaction supplies targets, updates Source
through the shared core path, then copies the resulting Source back to proxy. Phase 2
does not accept controller coordinate edits as deformation without that transaction.

## Topology changes

When persistent IDs referenced by controls disappear or become ambiguous, return `STALE_MAPPING`. Repair must be explicit; do not silently guess.

Fingerprint base connectivity including faces, not only counts/counters. External
topology edits can preserve counts/control IDs but change patches. On mismatch, block
the prototype until explicit validation/repair accepts topology and updates generations.
Never reassign ambiguous referenced IDs silently. New unreferenced IDs can be assigned
only during explicit validation, not as a side effect of starting deformation.

## Proxy deletion

Rebuild entirely from Source-owned definitions. No Source coordinate changes are allowed during rebuild. Preserve Source-owned hide
masks; rebuild is not Reveal All. Reveal resamples hidden geometry from current Source.
Visibility/network changes invalidate patch, constraint and distance caches; topology
validation includes mask IDs. No cached pre-hide coordinates are authoritative.

Create/remove validates effective union and prunes obsolete masks without revealing
overlaps. Cache keys include Source UUID, topology fingerprint, network revision and
proxy generation. Distances/weights rebuild from new P0; topology-only keys cannot
justify coordinate-dependent reuse. Source metadata cannot be overwritten from proxy.

# Multiple Templates and Context

**Status: Normative**

Each registered Source has a stable template UUID and at most one primary Control Proxy.

Context resolution:

- active Source → resolve its SourceRecord and Proxy;
- active Proxy → resolve its owning Source UUID;
- agent call → explicit Source/template UUID.

Never rely on object names as identity.

The prototype rejects shared editable meshes with SOURCE_NOT_EDITABLE and a Make Single
User recovery action, not an automatic copy. Source UUID plus local element/control ID
is the canonical key. Independent duplicates may retain local IDs/masks but need a new
Source UUID and independent proxy. Validate duplicate UUID collisions before editing;
never choose owners by name/list order or let a copied proxy target the original Source.

If a Source is duplicated as an independent editable mesh, the duplicate receives a new template UUID while retaining copied control definitions/persistent topology IDs within its own namespace. Shared editable mesh datablocks should be made single-user before registration to avoid two Sources mutating the same geometry unexpectedly.

# Errors and Recovery

**Status: Normative behavior; code names may be refined before implementation**

Recommended stable statuses:

```text
OK
NO_CHANGE
INVALID_INPUT
OPERATION_BUSY
OPERATION_CLOSED
NO_ACTIVE_SOURCE
SOURCE_NOT_EDITABLE
PROXY_MISSING
PROXY_CORRUPT
STALE_MAPPING (legacy diagnostic; translated to TOPOLOGY_CHANGED in the UI)
TOPOLOGY_CHANGED
CONTROL_HIDDEN
EMPTY_SELECTION
NO_MOVING_TARGET
TARGET_CONFLICT
NO_AFFECTED_PATCH
NON_FINITE_RESULT
OPERATION_STALE
UNSUPPORTED_FEATURE
```

Rules:

- mapping/proxy failure never writes Source;
- non-finite result with unchanged identity/topology restores P0/proxy and cancels; topology/deletion failures follow operation-semantics.md limits;
- missing proxy is recoverable by rebuild if Source definitions are valid;
- a Source topology change pauses DANP without writing stale IDs. Undo restores
  the previous mapping when Blender can restore the mesh. Reset DANP is the
  explicit repair path: it removes the old controller/definitions and creates
  a fresh mapping from the current Source topology in one undoable operation;
- an unapplied modifier does not redefine the mapping. The proxy stays backed
  by base Source IDs while the overlay may follow evaluated cage geometry. An
  Apply operation that changes base topology pauses DANP and uses the same Undo
  or Reset recovery path;
- Reset Model restores the coordinate snapshot captured by the first Init on the
  same topology. It is separate from Reset DANP and is itself undoable. If the
  topology no longer matches that snapshot, Undo or Reset DANP is required first;
- user UI receives a short recovery-oriented message;
- agent receives a stable code plus machine-readable context.

NO_CHANGE is successful identity, not solver failure; clear prior preview writes too.
Invalid/busy/hidden/stale requests fail before new writes. An error during an existing
transaction cannot leave partial preview edits: recover/close according to operation
semantics. Report Source/element IDs and expected/actual revisions where available.

Rejecting a second/busy caller must not cancel or restore the legitimate owner's preview.
NO_MOVING_TARGET can be diagnostic context for successful NO_CHANGE, not a reason to
skip prior-preview cleanup. NO_AFFECTED_PATCH describes selected geometry with no faces.

# Blender Integration

**Status: Current DANP Form integration contract**

DANP Form can be implemented as a normal Blender Extension using Python APIs for mesh access, BMesh, PropertyGroups/attributes, modal operators, overlays, and keymaps.

## Mode policy

- Create controls from Source Edit Mode.
- Manipulate controls through the Control Proxy or a dedicated DANP Form tool in the 3D View.
- Source remains visible as the actual result.

Controller is a child object of Source, using the same local geometric frame. Move,
rotate or scale Source object carries controller exactly once. This is object
parenting, not nested controls. Phase 2 provides Source-to-controller coordinate
display refresh; reverse interaction is added in phase 4 through DANP Form targets
and transaction writeback, not uncontrolled two-way sync.

Phase 3 patch visualization is an overlay. Toggling it must not hide/exclude Source
geometry from core or change network masks/partition. Phase 4 must route controller
Edit Mode G/R/S through owned DANP Form operations; native Blender transforms alone
are not assumed to provide immutable-rest preview/cancel/undo semantics.

## Mesh access

When Source is in Edit Mode, implementation must use the edit-mesh/BMesh pathway rather than assuming `obj.data` coordinates are current. Object-mode operations may use standard mesh updates.

## Downstream modifiers

Core edits base Source coordinates. Subdivision/Armature/etc. may evaluate
afterward. An unapplied modifier never becomes the control mapping: the proxy
continues to follow base Source IDs while the overlay may use evaluated cage
geometry. Applying a modifier is treated as a normal Source topology/coordinate
edit. If the base topology fingerprint changes, DANP pauses and reports a
recovery action; it does not write stale IDs. Undo can restore the old mapping,
or Reset DANP can create a new mapping on the current mesh in one undoable step.

## Unsupported/uncertain Blender features

Shape Keys, Multires, non-manifold corner cases, and linked read-only data should be explicitly tested before claiming support. They are not reasons to complicate the first interpolation prototype.

Prototype default: reject Shape Keys, Multires, non-manifold topology,
read-only linked data and shared editable meshes before writes, with an explicit
UNSUPPORTED_FEATURE/SOURCE_NOT_EDITABLE. This is not a permanent product ban. Do not
apply/remove modifiers, copy data or make it local automatically to start an operation.

Mapping is against Source-local base geometry, not evaluated subdivisions/poses.
Capture object transforms for target conversion; reject singular matrices. Solve into
plain buffers, validate, then update mesh/BMesh through the correct mode path. Do not
deform numerically in depsgraph handlers. Version/platform packaging remains a release
test item; record the actual Blender version rather than claim untested compatibility.

# Blender Interaction Model

**Status: Normative UX intent; exact key binding is an implementation choice**

```text
Source: select vertices/edges → Make Control
Proxy: select a point / vertex strip / edge-span / loop → G/R/S
Transform: proportional → confirm/cancel
Release contour: DANP Form Hide Selected → other edits → Reveal
```

## Sidebar and control management — Phase 2 UX upgrade

Sidebar context follows the active Source or its bound controller. An unrelated
object or empty selection must not leave commands targeting the previous Source.
Identity binding, not display names, resolves the Source. Drawing the panel is read-only.

The product/sidebar name is DANP Form. Existing `dan_form` extension/operator/storage
identifiers remain compatible. Before binding, the model shows Init DANP Form.
After binding, it shows Reset Model and a Manage menu containing Reset DANP
Controls and Remove DANP Form. If the controller is missing, Rebuild Controller
replaces Reset Model in that row. Init is idempotent and rebuilds a missing
controller. Remove deletes the
controller, its unused mesh, Source-owned DANP Form definitions/masks/binding and
ID attributes. It preserves model geometry, unrelated properties, attributes and
Source Object/Edit Mode. It is one undoable addon operation.

Make Control keeps Source active in Edit Mode with its selection intact. Definitions
may overlap partly or completely; each list entry has its own UUID/name while the
proxy deduplicates Source geometry. List selection, rename and removal are UX actions;
removal deletes only membership and unused proxy elements, never Source topology.

List states On/Partial/Hidden are derived from canonical effective geometry, not
per-definition activation flags. Whole-line Hide uses edge intent plus standalone
point intent; shared masks may change other overlapping entries. Display tooltips
explain this. Selection never implicitly reveals hidden geometry.

A colored Source control overlay makes edges/points readable without altering Source
materials or geometry. When the controller is selected in Object Mode, the same
colored lines are read directly from the controller mesh, so they remain exactly on
the editable proxy after a control change. In Controller Edit Mode the overlay reads
the live controller BMesh and paints every effective enabled edge cyan. Blender's
native selected wire/vertex display remains authoritative for selection, so the addon
does not paint a duplicate orange copy over selected elements. Show
Overlay/X-Ray/Show Hidden are display-only and distinct from DANP Form Hide/Reveal;
rare display/maintenance actions belong in the list menu.
With X-Ray off, the overlay uses the normal depth test and is occluded by the opaque
mesh. X-Ray explicitly disables that test when the user needs to inspect controls
through the model.
Controller Edit keeps Blender's native selection tools as the only selection
surface. Box, circle, lasso, click, Shift and Ctrl selection operate directly on
the Controller Edit mesh; the control list remains the shortcut for selecting a
stored membership. DANP does not add a second hover picker, segment picker,
"select all" button or Add-to-Selection toggle that can compete with Blender's
selection state.
Overlay positions use one bulk mesh read and retained GPU buffers. Geometry
events, context, masks, selected row and object transforms invalidate the relevant
display; idle redraw only draws existing buffers. Topology/ID caches contain no
long-lived BMesh handles or coordinate buffers. Colored point markers represent
explicit point handles, including a point definition sharing an edge vertex;
ordinary edge endpoints use the colored line and Blender's native Edit selection.
The sidebar uses a Blender-native list: inline names and eye state, shared +/− and
up/down controls, and Sync below it only in Source Edit Mode. Clicking a row immediately highlights
its effective control geometry. In Source/controller Edit Mode it also replaces the
active mesh selection with that definition; in Object Mode it keeps object/mode.
Selecting a hidden definition never reveals its canonical masks.

Edit Control activates the model's controller, enters its Edit Mode and selects the
active definition. Back to Model returns to the Source in the Object/Edit Mode used
before navigating to the controller. Hide Controls / Show Controls applies canonical
Hide/Reveal to every definition and synchronizes every eye. If some geometry is
visible it hides all; if all is hidden it reveals all, including previously hidden
individual portions. It keeps object/mode; an empty controller can Show All in Edit.
Edit Control never reveals masks and is disabled on Source with no effective handles.
This replaces the old display-only bulk button; see [ADR-010](../decisions/ADR-010-bulk-visibility-and-segment-selection.md).
No repeated row action boxes or persistent Display/Maintenance blocks.

Creation (+), membership Sync and definition removal (−) belong to the model.
Controller sidebar/menu omit these actions and their operators reject controller
context. Sync replaces the active definition's membership from current Source
selection, preserving UUID/name/order and canonical shared masks. Coordinate display
sync remains automatic. Rename/reorder do not change deformation or network revision.
See the [current native list plan](../roadmap/phase-02-native-list-ux.md) for the
object/mode matrix, eye behavior and tests. Phase 2 does not enable deformation G/R/S.

## Selection and deformation

Selection is ordinary Blender Controller Edit selection. The list selects a stored
control quickly, after which the user can refine it with Blender's native tools.
There is no addon-specific hover preview or alternate segment grammar to maintain.

The cyan enabled-edge highlight is an optional draw-only layer, capped at 1.5 px
in controller Edit. It never captures mouse input or selects vertices. Native
orange selection remains authoritative; native selection-only changes invalidate
the omitted-edge batches so deselected edges become cyan immediately. Turning
Overlay off leaves native selection and temporary pick preview usable. DANP X-Ray,
native viewport X-Ray and wireframe permit overlay/picking through Source; DANP
X-Ray also temporarily sets owned controller wires in front and restores their
previous display setting when disabled or unregistered. Opaque picking uses Source
ray occlusion; overlapping visible projections still require visual review.
Preview Hidden is a Source-only display option, not Reveal or editable geometry.
Canonical proxy rebuild retains surviving controller coordinates and selection;
newly revealed IDs sample Source and start unselected. Hidden handles do not keep
an independent pose outside Source.
H hides selected edges in edge mode, preserving other lines at shared endpoints;
H in vertex mode hides nodes and all incident edges. Alt-H reveals all from current
Source positions. Partial masks produce Partial eye state for every affected group.

Vertex mode selects nodes; edge mode selects full represented Source spans. Mixed
selection is a union; span endpoints are selected, not implicit stationary nodes.
Loop selection excludes hidden portions. The initial selection starts the native
transform; during the operation every Controller vertex whose coordinate changes
from the pre-transform pose becomes an exact target, including unselected vertices
moved by Blender Proportional Editing. Enabled control vertices that do not change
hold their position.
Hidden portions are not selectable deformation handles until revealed.

The controller object is parented to Source, so object transforms follow Source.
Control vertex edits are a separate action through DANP Form transactions. Source
selection uses Source-backed lines; controller Object Mode uses controller-backed
lines, while Controller Edit Mode shows the actual editable wire geometry with the
cyan enabled-control highlight from the live controller BMesh.

Controller topology is fixed to the effective Source network. Moving existing
points is allowed; adding, extruding, duplicating, deleting, dissolving, merging,
subdividing, rewiring edges or filling faces is not. Context-specific shortcut
guards intercept common modeling keys on the controller only. Geometry events
validate IDs and connectivity, not just element counts. If a native menu/tool/MCP
command bypasses the key guard, restore the last valid proxy pose in place without
changing Source or leaving Controller Edit Mode. Source definitions and canonical
Hide/Reveal may legitimately rebuild the proxy. On reload/undo/redo/load, derive
expected topology from Source and rebuild the runtime recovery snapshot.
Phase 2 coordinate editing is still not mesh deformation; Phase 4 supplies that.

Show Patches, including any per-patch color toggle, controls overlay display only.
It never toggles patch deformation or removes Source faces from solve input.

Own transforms through a DANP Form operation for immutable rest, cancel and one undo.
Intercept proxy hide/reveal (for example H/Alt-H) only in DANP Form context; update
Source masks, effective network, display and patch cache together. Object/collection
visibility remains display-only. A hide command cannot merely toggle proxy hide flags.

Use labels/tooltips explaining Hide releases shape constraints and cuts; Reveal adopts
the current mesh contour. No separate activate/deactivate or parent/child control UI.
Enabled shared endpoints may remain visible when a neighboring span is hidden.

Hide/reveal is a separate undo step, with no Source coordinate write. Finish/cancel the
active transform first. Preserve original mode/selection safely. Expose profile/radius
or Whole Patch, not solver-specific controls. Refine must not act as Reveal.

# Blender Storage and File Lifecycle

**Status: Implementation-ready behavior**

Persist Source element IDs as mesh attributes and project/control records as registered properties attached to the Source object/mesh. Proxy metadata only needs enough information to resolve its Source and per-element bindings; all meaningful control definitions remain Source-owned.

On save/load:

- Source geometry/metadata and canonical hidden vertex/edge masks persist;
- proxy may persist or be rebuilt;
- runtime patch/distance/interpolation caches are discarded/recomputed.

On undo/redo:

- clear transient caches;
- at the next sync boundary validate Source metadata and resample/rebuild Proxy;
- recovery synchronization must not create a second undo entry.

On Source deletion, the lifecycle handler removes only Controller objects and
auxiliary face/prototype objects carrying an explicit DANP Source ownership
marker. It never guesses from object names or collections, so unrelated assets
remain safe. On Proxy deletion, Source remains valid and can rebuild it.

If Source topology changes outside DANP, the stored ID mapping is kept intact
but the pair enters a paused state. Commands do not write against stale array
indices. Undo restores the previous Source topology and mapping; Reset DANP
discarding the old definitions and rebuilding the controller is the explicit
repair operation for the current topology.

Hide/reveal is its own undoable state edit with zero Source coordinate changes. Undo/redo
restores masks and invalidates network/patch/constraint caches. Proxy rebuild and load
must not reveal everything or recover old hidden coordinates.

# Human and AI Shared Primitives

**Status: Normative**

AI does not receive a separate deformation solver or direct patch-writing API.

Both human and agent use the same conceptual operations:

```text
select enabled control elements
hide / reveal whole controls or Source-backed portions
translate / rotate / scale
or set explicit proxy-knot targets
set proportional settings
begin / update / commit / cancel
```

Those inputs pass through the same steps:

```text
interaction → Dense Target Set → affected patches → interpolation → Source writeback
```

That pipeline applies to deformation inputs. Hide/reveal instead updates Source masks,
recomputes the enabled network/patch caches and resamples proxy; it writes no Source
coordinates. It is a separate structural command, outside an active transform.

An agent may skip mouse simulation by providing numeric transforms/targets, but must not bypass target expansion, patch scope, proportional placement, or operation-rest semantics.
UI and agent transforms resolve through the same canonical operation input:
`MOVE`, `ROTATE` or `SCALE`, Source-local/world space, pivot, absolute
translation/rotation/scale and proportional settings. The core then resolves
selected Source IDs to absolute targets from Operation Rest and applies the same
control-owned transform field used by Controller Edit.

## Selection identity rule

The selection primitive is `dan_form.blender.selection._source_selection` and is
shared by the UI `+` operator and the agent facade. It refreshes BMesh lookup
tables but records `VID_ATTR`/`EID_ATTR` persistent IDs. BMesh vertex/edge indices
are transient diagnostics only; agents must never persist or submit them as
control membership. After topology changes, re-read the selection snapshot and
the topology fingerprint before issuing another command.

# Agent API Contract

**Status: Logical contract; transport and exact signatures are implementation details**

```text
list_sources() / get_source(source_id)
list_controls(source_id) / get_proxy_geometry(source_id)
list_patches(source_id) / get_patch(source_id, patch_id)
get_control_visibility(source_id)
select_elements(source_id, node_ids=[], span_ids=[], control_ids=[])
begin_operation(source_id, selection, proportional, expected_network_revision)
translate(operation, delta, space)
rotate(operation, rotation, pivot, space)
scale(operation, scale, pivot, space)
set_knot_targets(operation, targets)
update_operation(operation)
commit_operation(operation) / cancel_operation(operation)

create_control_from_source_selection(...) / remove_control(...)
create_control(source_id, source_vertex_ids=[], source_edge_ids=[])
hide_control_elements(source_id, node_ids=[], span_ids=[], control_ids=[])
reveal_control_elements(source_id, source_vertex_ids=[], source_edge_ids=[], control_ids=[])
reveal_all_controls(source_id)
rebuild_proxy(...) / simplify_control(...) / refine_control(...)
```

Visibility queries enumerate hidden Source IDs even when those elements are not in the
visible proxy. Hide uses canonical masks and whole/partial selection semantics. There
is no separate set_control_active command: hide/reveal is the user-facing mechanism.

Node-only targets select only bound vertices; span transforms select represented dense
geometry. Queries report current Source positions, effective enabled network and its
revision. Hidden direct edit requests return CONTROL_HIDDEN. Stale generation/network
requests fail before Source writes. Only one deformation transaction owns a Source.

Results report status, changed vertex count, warnings and Source/network revision.
Hide/reveal returns zero coordinate changes and invalidates scope. Human and agent
use the same targets, constraints and interpolation, including shared-vertex priority.

Bind operation handles to Source UUID, topology fingerprint/generation, network revision,
proxy generation and owner token; check on every action. Rebuild can invalidate old
node/span handles without changing the effective network. Queries return revisions,
current positions and Source-scoped IDs.

Transforms are absolute relative to operation start: repeating a delta does not accumulate.
Explicit updates must resolve the complete selected target set; reject missing/extra or
non-finite IDs instead of guessing. Node-only convenience calls have node-only selection.
NO_CHANGE is a successful identity result; busy/closed/invalid requests use stable errors.

Hide/reveal reports changed masks, released/retained junctions and network revision,
with zero Source coordinate change. Unchanged repeats do not increment revision.
Queries never start a deformation transaction or write Source coordinates.

## Delivery in the five-phase roadmap

Phase 2 implements control creation/masks/rebuild as shared internal primitives.
Phase 3 supplies derived patch queries. Phase 4 provides a minimal numeric facade
for the same transaction/targets as UI; phase 5 verifies it through actual MCP.
Source-ID-based create_control avoids requiring an agent to manipulate UI selection;
it resolves the same source-backed definition as Create from Source selection.
Patch IDs are derived handles tied to topology/network revision, not permanent IDs.
Source state is revalidated before operations; agents must requery after rebuild or
structural changes. Exact public Python/operator signatures are documented from the
implementation at handoff, not inferred from this logical list.

Simplify/refine and sparse-span APIs are optional extension capabilities. Advertise
what the installed build supports; unsupported capability requests return a clear
error rather than silently succeeding. Reference-based testing in phase 5 supplies
ordinary targets, with no additional mesh-write API or reference solver.

## Blender facade (current build)

When running inside Blender, external agents should import `dan_form.agent` and
use the facade instead of editing `dan_form_controls` or indexing `mesh.vertices`
directly:

```python
from dan_form.agent import (
    inspect_source_selection, create_control_from_current_selection,
    begin_operation, update_operation, commit_operation, cancel_operation,
)

selection = inspect_source_selection()
# persistent_vertex_ids / persistent_edge_ids are canonical; mesh_*_indices are
# diagnostics only and may change after topology operations.
result = create_control_from_current_selection(
    name="Shoulder Base (Left)", side="LEFT", region="SHOULDER_BASE"
)

# Controller Edit must be active for the transaction facade.
begin_operation()
update_operation((0.02, 0.0, 0.0), radius=0.0)
commit_operation()       # or cancel_operation()
```

`create_control_from_current_selection` calls the same registered operator as the
Sidebar `+` button. It returns the canonical control definition, a persistent-ID
selection snapshot, and validation data. Stable failures include
`NO_ACTIVE_SOURCE`, `SOURCE_EDIT_MODE_REQUIRED`, `NO_SOURCE_SELECTION`,
`SOURCE_ID_LAYERS_MISSING`, `STALE_MAPPING`, and `CONTROL_CREATE_FAILED`.
Display names are normalized to a deterministic suffix when a duplicate is
requested; agents should use `control_uuid` as identity and should include
`side` (`LEFT`, `RIGHT`, or `CENTER`) and a semantic `region` when known.
Agents must re-query after rebuilds and must never write the control JSON directly.

# Reference Fitting Extension

**Status: Extension — not part of the first core prototype**

Reference fitting may use front/side/other images or 3D targets to calculate where selected controls should go. It must stop at target generation.

```text
reference evidence
      ↓
control target positions / transforms
      ↓
normal DANP Form target expansion
      ↓
normal patch interpolation
      ↓
Source Mesh
```

Reference code must not:

- write arbitrary Source vertices directly;
- maintain a separate deformation solver;
- introduce front/side/anatomy semantics into core controls;
- bypass operation rest, patch scope, proportional, cancel, or undo.

Camera calibration, silhouette extraction, correspondences, and multi-view optimization are separate extension problems and should be designed only after core control deformation is validated.

The accepted phase-5 test uses references without requiring this automated extension:
human or external agent observes front/side images, creates ordinary controls and
chooses target positions through the shared core path. A front/side contour is a
normal Source-backed control line, not a special solver boundary type.

# Advanced Interpolation Options

**Status: Experimental options only**

The baseline in `../core/interpolation-baseline.md` is intentionally simple. Promote a more complex method only after a reproducible failure and benchmark evidence.

## Failure → smallest next experiment

### Visible bands or sampling-density artifacts

Try smoother displacement reconstruction or improved geometric sampling while preserving enabled unselected hard constraints, selected targets, hide masks, grouping independence and proportional placement. Do not fix artifacts by moving unselected control vertices.

### Poor behavior on irregular multi-boundary patches

Try a smoother interpolation-coordinate field. Harmonic/biharmonic coordinates are candidates, not product requirements.

### Excessive shear or detail loss under large rotation/nonuniform change

Try a constrained local differential/detail relaxation **after** the baseline displacement and prove that:

- hard control targets remain exact;
- no-target stays a no-op;
- it does not pull toward the historical template;
- the failing benchmark improves without making ordinary cases less predictable.
- finite-radius zero-influence vertices and captured-scope preview cleanup remain exact;
- logical grouping, hidden masks and shared stationary control constraints remain unchanged.

Laplacian or ARAP-like methods are possible experiments here. SVD/iterative solvers are implementation consequences of an experiment, not core invariants.

### Performance failure

Optimize distance caching/data layout or move a validated method to an accelerated backend. Do not redesign user behavior to accommodate a solver.

# ADR-001 — Source Mesh Is Geometric Truth

**Decision:** committed DANP Form operations write real Source coordinates. Proxy/control metadata may remain, but Source shape does not require a permanent evaluator.

**Reason:** DANP Form is a modeling tool; deleting controls/proxy must not undo committed modeling.

# ADR-002 — Control Proxy Is Rebuildable Input

**Decision:** Source owns control definitions. One lightweight proxy per Source is the normal interaction object and can be rebuilt without changing Source geometry.

**Reason:** separates dense production topology from sparse interaction while avoiding a second geometric source of truth.

# ADR-003 — Patches Are Derived from Enabled Source Control Edges

**Decision:** remove face adjacency across effective enabled control edges (hidden edges excluded; see ADR-008) and use connected components as patches. No manual barrier flag is required in core.

**Reason:** matches the intended topology rule, including open chains that do not actually separate a surface.

# ADR-004 — Each Operation Uses Current Committed Shape as Immutable Rest

**Decision:** capture current Source at operation start and use it for every preview in that operation. The original template is reset/compare data only.

**Reason:** prevents preview drift and keeps sequential modeling cumulative rather than modifier-like.

**Decision:** all input producers resolve to the same Dense Target Set, affected patches, proportional semantics, and Source writeback.

**Reason:** keeps AI inspectable and prevents hidden alternate deformation behavior.

**Decision:** test a small current-shape/displacement candidate, proportional and enabled

**Decision:** selected span coverage is explicit selection mapping; user proportional radius/profile attenuates the patch displacement once after interpolation.

**Reason:** avoids accidental double falloff and gives one clear control for locality.

# Geometry Test Cases

**Status: Required prototype evidence; constraints and scope are mandatory**

Record fixture geometry, explicit selection, effective network, targets, profile/radius,
result coordinates and before/after views. Quality-only observations cannot override
hard constraints. No midpoint half-motion or universal affine response is assumed.

## G1 — No-op
All selected targets equal P0; every Source coordinate stays unchanged through previews.

## G2 — One moving boundary
Grid strip with A selected, B enabled stationary. A hits Q; B remains P0; outside scope
is untouched. Compare Whole Patch and finite profiles/radii on the same targets.

## G3 — Two boundaries scale
Both boundaries hit T(P0). Inspect interior continuity and proportional response;
do not require a fixed midpoint displacement or exact affine shape from every profile.

## G4 — Limb form
Two ring controls on a curved/bumped limb. Inspect whether patch form is useful under
proportion edits. Detail follows patch deformation; add controls for separate detail edits.

## G5 — Ring rotation (quality evidence)
One selected ring rotates, other enabled controls fixed. Measure shear/smoothness;
decide if a targeted interpolation improvement is needed.

## G6 — One exact control vertex
Only selected vertex moves; all other enabled control vertices stay P0. Patch response
obeys proportional/scope without moving stationary control neighbors.

## G7 — One sparse knot
Dense curved path with sparse A–B–C; select B only. B hits Q. A/C and every omitted
enabled Source control vertex stay P0. No automatic moving targets along AB/BC.

## G8 — Sparse span transform
Select AB span and rotate/scale it. Represented selected dense vertices hit T(P0).
Unselected spans hold except common endpoints selected by AB; hidden gaps are excluded.

## G9 — Patch connectivity
Interior open line does not split unless adjacency disconnects. Boundary-to-boundary
cut can split. Single cylinder longitudinal line need not split into two patches.

## G10 — Repeated operations
Operation B captures A's committed result as P0; historical snapshot does not pull.

## G11 — Irregular multi-boundary patch (quality evidence)
Inspect smoothness/sampling artifacts with varying displacements and valence. Reproduce
a failure before adding an advanced method; preserve all hard constraints throughout.

## G12 — Enabled longitudinal line
Limb U/L loops plus D. Scale U only, then U+L. Selected loop vertices hit Q; all
unselected enabled D/L vertices stay P0. Selected shared junctions move with loops.

## G13 — Hide longitudinal line
Hide D; derive patches again. D interior is no longer a constraint/cut, but U/L
junctions remain enabled through loops. Scale U or both loops; released vertices
receive ordinary patch output within influence. Hiding itself deforms nothing.

## G14 — Reveal at new contour
After G13 commit, reveal D. Positions/bindings match current Source exactly; no
pre-hide coordinate restore. Masks/state survive save/load and proxy rebuild.

## G15 — Partial hide and junctions
Hide middle spans and separately nodes. Retained supporting edges keep endpoints
enabled; hiding nodes disables incident cuts. Validate actual merge/connectivity,
overlapping definitions, partial loops and reveal with independently hidden edges.

## G16 — Grouping independence
Same Source topology, masks, selected IDs, targets and settings represented as separate
lines or one network yield equivalent patch partition, constraints and output. Duplicate
memberships must not add interpolation weight or invisible constraints.

## G17 — Preview returns to rest
Start at P0, move a control, then set its targets back to P0 before confirm. Every earlier
previewed vertex, including hidden paths, returns exactly to P0. Repeat with only some
selected targets returning to rest and with radius shrinking. No residual deformation
may remain outside current influence; vertices outside captured scope stay untouched.

## G18 — Hide intent at junctions
Hide whole D in the U/L/D fixture using edge intent: both loops remain enabled and D's
unsupported interior releases. Hide the U–D node explicitly: incident edges become
ineffective. Reveal an edge clears endpoint node masks but not separately edge-hidden
branches. Repeat hide/reveal: no coordinate change or duplicate state revision.

## G19 — Invalid and degenerate inputs
Test zero-length edges, tiny/large scaled coordinates, empty selection, no moving targets,
no incident faces, non-finite targets and invalid radius. Return finite validated output
or an explicit error before writes. Never divide by an empty sample sum or write NaN.

## G20 — Coordinate-space parity
Same explicit Source-local targets from local/world transforms yield equivalent output.
Use translated/rotated/nonuniformly scaled objects and reject singular transforms. Radius
comparisons use documented consistent units; unexpected mixed-space behavior fails.

## G21 — Definition lifecycle
Create an overlapping definition over hidden geometry: no silent reveal or extra weight.
Remove one overlapping definition: masks and shared supported geometry remain coherent.
Remove last membership: no Source topology edit; obsolete masks/handles are pruned.

## Measurement contract
For pure numerical fixtures record a scale L=max(rest bounding-box diagonal, 1e-12).
Use float64 candidate buffers; an initial comparison tolerance 1e-8*L is a prototype
test parameter, not a frozen production threshold. Check selected targets against Q.
Copy stationary/out-of-influence/rest-cleanup vertices from P0 exactly; a nonzero drift
cannot be excused by a loose quality tolerance. Blender storage tests compare against
stored/round-tripped targets and require unchanged vertices/cancel coordinates exact.

Record before/after and displacement maps for G4/G5/G11 and proportional comparisons.
Quality approval must name inspected fixtures/settings and unacceptable visible artifacts;
recording images without deciding acceptance does not pass Gate C.

# Blender Integration Test Cases

**Status: Required progressively in phases 1–5; deformation follows pure geometry gates.**

## Early integration — phases 1–3

- Source coordinate edits in Object/Edit Mode → displayed controller refreshes; command boundaries still validate mapping.
- Patch overlay toggle → no Source-coordinate, network-mask, revision or partition change.

- Register Source → persistent IDs survive save/reload.

- Coordinate-only Source edit outside DANP Form → visible Proxy refresh plus revalidation/resync at the next operation.
- Destructive topology change → stale mapping detected; deformation blocked.
- Transform preview → every mouse/numeric update uses immutable `P0`.
- Normal cancel with unchanged identity/topology → exact operation-start Source/Proxy restored.
- Confirm changed geometry → one logical undoable operation; identity confirm → successful NO_CHANGE without a meaningful extra undo edit.
- Two independent Sources in one scene → context never crosses.

separately from parity on equivalent targets. Test stale/busy/closed/retry paths and
report unavailable transport as BLOCKED, not PASS.

# Leg Control Examples

**Status: Normative constraints/scope; interior motion depends on proportional and method**

A limb has upper loop U, lower loop L and longitudinal line D. These are example labels,
not core roles. D alone may not divide a cylindrical surface into two patches.

## Scale U while D is enabled

U hits its selected scale targets. L and unselected D vertices remain at P0. The U–D
junction is selected through U, so it moves too; other D vertices remain fixed.
Adjacent patch interiors deform using proportional and current patch shape.
No fixed half-motion at the midpoint is promised.

## Scale U and L while D is enabled

Both loops scale. Unselected D interior remains fixed, so it may hold a bulge between
the loops. Both selected loop–D junctions move with the loops.

## Hide D, then scale U or both loops

D edges stop cutting. Its interior vertices stop anchoring unless other enabled
geometry also supports them. Recompute patches. With U selected, L stays fixed;
with U and L selected, both loops move. Former D vertices follow allowed patch motion
under proportional, not a stored old contour.

Hide whole D uses edge intent, not Hide Nodes on its junctions. Thus U/L remain intact.
Explicitly hiding a junction node instead opens every incident control edge there.

Reveal D after commit: sample the current leg contour and restore its roles there.
No snap to old positions is allowed.

## Hide only D's middle segment

That portion stops cutting/holding; retained portions still constrain. Shared endpoints
can stay fixed through retained edges. Include endpoint nodes in Hide when they too
should be released. Actual connectivity decides whether patches merge.

## Pull part of D inward

Select a strip/span. Its vertices receive targets; other enabled geometry stays fixed,
except junctions included in the selection. No front/side deformation mode is required.

A bump inside a patch follows patch deformation. Create additional controls around/on
it for separate manipulation; the core does not infer a protected feature.

# ADR-008 — Enabled Controls Hold; Hidden Controls Follow Source

**Status: Accepted by the product owner, 2026-09-18**

**Decision:** enabled unselected Source control vertices are stationary. Selected
node/span/strip/loop geometry moves; a selected target wins at shared junctions.
DANP Form Hide removes constraint and cut roles for hidden geometry. Reveal samples
current Source coordinates, not pre-hide positions. Whole and partial hiding share
canonical Source element masks defined in core/control-model.md.

**Reason:** select which contours hold and which follow the mesh using selection and
hide/reveal, without parenting, nested patches or a separate deactivate feature.

**Supersedes:** display-only DANP Form hiding, separate deactivate UI, automatic moving
targets on unselected dense vertices after sparse-knot edits, and weighting by logical
control memberships. Ordinary object/collection display hiding remains separate.

**Consequences:** persist masks; resample on reveal/rebuild; invalidate caches; make
hide/reveal undoable; freeze effective network during transforms. Validate G12–G16 and
Blender lifecycle cases. Final interpolation remains subject to prototype evidence.

Whole edge-backed controls hide by edge intent so junctions retained by other enabled
lines survive. Explicit node hiding disables all incident edges at the node. The
core/control-model.md mask rules compose on shared Source geometry; they are not
per-definition ownership. These clarifications preserve the agreed two-loop/line example.

# Technical Options — Non-Normative Notes

Earlier design drafts made harmonic interpolation plus similarity-preserving ARAP a normative production solver. That was premature because the product behavior had not first been validated with a simpler displacement model.

Useful method families remain available as research tools:

- graph/geodesic distances for topology-aware locality;
- Shepard/inverse-distance blending for a simple baseline;
- harmonic/biharmonic coordinates for smoother interpolation;
- Laplacian editing for differential-detail preservation;
- ARAP/local-global methods for strong rotational preservation;
- cages/lattices for alternate control representations.

None is selected by product definition alone. The prototype matrix in `../testing/geometry-cases.md` determines whether the baseline is sufficient and which failure deserves the next experiment.

## Những quy tắc đã chốt

1. **Một nguồn hình học:** Source giữ tọa độ, định nghĩa control, IDs và trạng thái ẩn.
   Controller là mesh vertex/edge không face, có thể dựng lại. Đường nhìn ở front/side
   vẫn là đường trong không gian 3D, không phải bản sao 2D độc lập.
2. **Object controller là con của Source:** di chuyển/xoay/scale object Source kéo
   controller theo, không nhân transform hai lần. Đây là quan hệ object Blender,
   không phải quan hệ cha/con giữa các đường control.
3. **Đồng bộ có hướng rõ ràng:** ngoài thao tác DANP Form, Source cập nhật controller.
   Trong thao tác phase 4, controller cung cấp target; core cập nhật Source rồi
   đồng bộ controller từ Source. Không để hai object tự ghi qua lại.
4. **Bật là ràng buộc, ẩn là giải phóng:** mọi vertex control đang bật không được
   chọn giữ nguyên trong phép biến dạng. Vertex giao nhau được chọn vẫn di chuyển.
   Hide/Reveal theo mask nguồn, không cần thêm deactivate hay lồng control.
5. **Patch theo topology:** các face liên thông qua cạnh không bị control đang bật
   cắt tạo thành patch. Đường mở không nhất thiết chia được patch.
6. **Ảnh hưởng theo kết nối:** một vertex control có thể tác động lên tập vertex
   nối tới nó qua edge trong patch kề, tùy proportional và ràng buộc. Tập này có
   thể phân nhánh, không có quy tắc một control vertex sở hữu một chuỗi duy nhất.
7. **Nền mỗi thao tác là mesh hiện tại:** snapshot P0 bất biến cho mọi preview;
   cancel khôi phục, confirm ghi mesh thật. Không kéo về template lịch sử.
8. **Chốt nội suy ở phase 4 bằng thử nghiệm:** dùng candidate đơn giản để đo hành
   vi, so sánh proportional và chất lượng. Không bắt buộc solver phức tạp trước.

# Review of the Previous Documentation

**Status: Audit**

The previous DANP Form documentation contained several strong architectural decisions but over-specified the numerical solver before the simplest product behavior had been validated.

## Keep

- Source Mesh as the geometric source of truth.
- Separate rebuildable Control Proxy.
- Persistent Source element IDs and Source-owned Control Definitions.
- Topology-derived patches; open chains only cut when connectivity really disconnects.
- Current Source at operation start as immutable Operation Rest.
- Exact cancel and one-commit/one-undo semantics.
- Multi-template identity/context handling.
- Human and AI using the same primitives.
- Reference fitting producing control targets only.

## Rewrite

- **Control selection:** distinguish node, Source span, and whole-control selection; define partial-line behavior explicitly.
- **Sparse controls:** spans explicitly select dense Source paths; knot-only edits leave omitted enabled vertices fixed. The previous automatic neighbor expansion is superseded by ADR-008.
- **Deformation:** describe required geometry behavior first, then a simple prototype interpolation.
- **Hide/reveal:** canonical whole/partial masks release constraints/cuts; reveal samples current mesh. Display-only hiding and separate deactivation are superseded.
- **Proportional:** apply once to patch propagation instead of mixing user falloff with multiple solver stages.
- **Testing/roadmap:** validate geometry behavior before performance/production claims.

## Remove from core

The following are no longer mandatory core architecture:

- harmonic vector fields;
- ARAP/similarity-ARAP;
- SVD;
- PCG;
- a required multi-stage “base field + shape-preserving relaxation” pipeline;
- a required NumPy/native numerical backend;
- solver-family-specific caches and numerical thresholds;
- claims that the design is production-ready before behavior prototypes pass.

They may return only as evidence-driven experiments.

## Move to extensions

- detailed reference-image fitting;
- collision/volume preservation;
- advanced interpolation/shape-preservation methods;
- aggressive performance acceleration;
- automated AI fitting strategies beyond the shared core API.

# Documentation Audit — 2026-09-18

**Status: Review of specifications; not evidence of a working add-on**

Reviewed all modular documentation, root guidance/readmes, ADRs and implementation tasks.
The accepted modeling idea is unchanged: Source-backed selection drives deformation
within topology patches using proportional and current patch form; enabled unselected
controls hold, hidden contours can follow mesh and reveal at current positions.

## Corrections

| Finding | Resolution |
|---|---|
| Whole Hide could be read as hiding junction nodes and breaking retained loops | Whole edge-backed Hide uses edge intent; explicit node Hide affects every incident edge |
| Sparse selection could be mistaken for implicit neighbor motion | Knot-only selects one bound vertex; spans explicitly select represented dense geometry |
| Identity/radius-shrink previews could leave earlier displacement | Capture incident-patch scope and rebuild output from P0 for every update; G17 |
| Per-update scope versus no-outside-write rules were ambiguous | Current deformation scope and bounded prior-preview cleanup are documented separately |
| Errors/busy/closed handles lacked defined write behavior | Validate generations/ownership/input, preserve legitimate owner on busy rejection, reject closed handles |
| External topology could preserve element counts | Require connectivity/faces fingerprint and explicit validation; no stale-index rollback |
| Coordinate caches and Source/world target spaces were underspecified | Freeze P0/transform frame; rebuild coordinate-dependent buffers; consistent radius units |
| Sparse/agent tests appeared before their implementation phases | Five-phase roadmap: Gate D in phase 4, Gate F in phase 5, optional Gate E after core |
| Numerical candidates were sometimes described as product mandates | Readme/authority rules distinguish normative behavior from replaceable methods |
| Prototype unsupported cases remained unclear | Reject non-manifold, Shape Keys/Multires, shared/read-only data before writes; future support stays open |
| Old 0–8 tasks contradicted the agreed product milestones | Replaced by five phase tasks with work packages, dependencies and P1–P5 gates |
| Controller follow behavior and apparent 2D lines were ambiguous | Source-child object, same local frame, 3D vertex/edge proxy and directed coordinate sync |
| Patch toggles could be mistaken for excluding solve input | Overlay display-only; effective control Hide changes actual face partition |
| One vertex/one chain could prescribe an unsupported mesh mapping | Influence is graph-connected vertices in incident patches and may branch |
| Reference testing implied an automatic fitting feature | Phase 5 tests human/agent-generated targets; automatic image processing stays extension |

The five-phase [roadmap](../roadmap/implementation-plan.md),

# ADR-009 — Five-phase development and controller lifecycle

**Status: Accepted — user agreement, 2026-09-18.**

## Decision

Develop in five phases: extension/sidebar/Source/controller; Source-backed control
creation and sync; topology patch visualization; Edit Mode deformation/proportional;
user and external-agent validation through MCP with reference images.

The controller object is a child of Source, sharing its local coordinate frame.
Object move/rotate/scale follows Source exactly once. This does not create parenting
between control definitions and does not change ADR-008 enabled/hidden constraints.

Phase 2 updates displayed controller coordinates from Source. Phase 4 supplies the
reverse interaction through canonical targets and transactions, followed by Source
to proxy resync. Controller is not independent geometric truth. View-aligned wire
controls remain 3D Source-backed vertices/edges, not independent 2D geometry.

Patch display toggles are UX only. Actual partition changes come from effective
control edges and topology, including DANP Form Hide/Reveal. A selected control
vertex influences graph-connected vertices in incident patches subject to fixed
constraints/proportional; no unique unbranched vertex chain is prescribed.

## Consequences

Basic install/control/patch UX can be tested before the numerical prototype. Phase 4
must pass geometry and quality gates before its interactive deformation is accepted.
Numeric facade implementation supports phase 4 tests and phase 5 MCP validation.
Sparse controls, advanced solvers and automatic reference fitting remain optional
extensions. Phase 5 reference fitting means human/agent-driven targets through core,
not mandatory image extraction/calibration. No new solver family is frozen here.

## Ranh giới trách nhiệm

| Thành phần | Trách nhiệm | Không sở hữu |
| --- | --- | --- |
| Source storage | Source UUID, persistent IDs, control definitions, masks, revisions | Proxy làm nguồn tọa độ thứ hai |
| Mesh adapter | Đọc/ghi base mesh đúng Object/Edit Mode, kiểm tra topology | Công thức nội suy |
| Proxy adapter | Dựng vertex/edge, parenting, selection map, hiển thị/sync | Bản lưu template độc lập |

Giai đoạn đầu exact proxy: mỗi vertex hiển thị ánh xạ một Source vertex ID. Chưa làm
sparse. Chỉ `bpy`/adapter giữ object handle; core nhận IDs, connectivity, tọa độ và
buffer số. Trước ghi kiểm tra targets hữu hạn, identity/topology, revision/generation

## Dữ liệu và cache

Lưu định nghĩa và trạng thái đủ để dựng lại proxy/patch sau mở file. Transaction,
buffer P0, preview, cache khoảng cách và overlay là runtime, không lưu như sự thật.
Cache partition phụ thuộc topology và effective network; cache khoảng cách/weights
còn phụ thuộc P0 và proportional. Đổi tên logical control không đổi lời giải.

Parent controller giữ cùng hệ tọa độ local với Source, không thêm offset/scale riêng.
Transform object Source không phải biến dạng control. Proxy rebuild giữ định nghĩa/
mask, không Reveal All. Duplicate Source có Source UUID mới; kiểm tra không bind vào
Source gốc. Các generation/closed-operation checks phải có trước phase 4 ghi preview.

## Đồng bộ và thao tác

Ngoài transaction: nhận tín hiệu Source thay đổi → đánh dấu dirty → cập nhật proxy
nhẹ trong context an toàn. Thử cả BMesh khi đang Edit Mode. Không chạy solver trong
depsgraph handler. Mốc lệnh vẫn revalidate Source; tín hiệu UI không thay kiểm tra
identity. Loại event/timer cụ thể chọn bằng thử phase 2, ghi độ trễ đo được và giới hạn.

Trong transaction: resolve selection → chụp P0 và union các patch kề → sinh target
tuyệt đối từ đầu thao tác → solve/validate buffer → ghi preview Source → resync proxy.
Preview sau reset buffer về P0 trước khi solve scope hiện tại, để radius nhỏ lại hoặc
target quay về P0 không để lại biến dạng cũ. Confirm/cancel đóng handle và dọn runtime.

Các lệnh cấu trúc control/mask/rebuild khi đang thao tác trả `OPERATION_BUSY`.
Topology bị đổi ngoài dự kiến phải chặn tiếp tục, không rollback theo index cũ. Quy
tắc recovery đầy đủ nằm ở [errors-and-recovery.md](../architecture/errors-and-recovery.md).

## Hiện trạng trước đợt triển khai UX đầu tiên

Trong `dan_form/__init__.py`, panel và operator dùng `scene.dan_form_source` được
chọn thủ công. Make Control gọi chuyển Object Mode rồi chọn controller. Sidebar chỉ
hiện số control; chưa có danh sách, chọn nguyên định nghĩa, đổi tên hay xóa từng
định nghĩa. Controller dùng wire mặc định, chưa có lớp vẽ màu trên Source.

Định nghĩa đã có UUID và Source vertex/edge IDs; masks đang lưu chung trên Source.
Có thể dùng nền dữ liệu này, nhưng phải hoàn thiện thao tác Edit Mode, union overlap,
sync nhiều model và lifecycle trước khi coi nâng cấp UX là hoàn tất. Kiểm tra mã
không chứng minh các gate runtime đã pass.

## 1. Sidebar theo đối tượng đang thao tác

Một resolver dùng chung cho panel và operator xác định Source từ **active object**:

| Active object | Sidebar |
| --- | --- |
| Mesh chưa khởi tạo | Tên mesh và nút Initialize; chưa hiện quản lý control |
| Source đã khởi tạo | Danh sách và trạng thái của chính Source đó |
| Controller DANP Form | Resolve Source qua identity binding và parent; cùng danh sách như Source |
| Không chọn / object khác | Hướng dẫn ngắn chọn mesh hoặc controller; không giữ thao tác trên model cũ |
| Mapping thiếu, UUID trùng hoặc parent sai | Báo lỗi binding và hướng phục hồi; không đoán Source theo tên |

Nhiều object được chọn thì active object quyết định context. Trong multi-object Edit
Mode chỉ đọc selection của Source active; không sửa các mesh khác. Source không đủ
điều kiện chỉnh sửa có lý do cụ thể và nút thao tác bị khóa.

Không dùng dropdown Source làm luồng chính. Scene pointers cũ chỉ có thể là cache
tương thích, không phải nguồn quyết định context. Panel draw không tạo IDs, ghi
metadata hay rebuild. Các lệnh revalidate binding trước khi ghi; không dùng context
đã cache từ model trước. Sync phải theo dõi các Source có controller, kể cả khi người
dùng vừa chuyển sang model khác.

## 2. Tạo đường mà không ngắt thao tác modeling

Luồng chính: chọn Source → Edit Mode → chọn điểm/cạnh/dải/loop → **Make Control** →
đường được tô rõ và danh sách thêm một dòng → tiếp tục chọn đường kế tiếp ngay.

- Kết thúc thành công vẫn là Source active, Edit Mode, giữ selection và selection
  mode; không chọn controller thay người dùng. Lỗi cũng không làm mất context.
- Đọc IDs, topology và tọa độ từ BMesh đang edit; không ép Object Mode chỉ để đọc
  `mesh.data`. Cập nhật proxy khác object qua adapter an toàn.
- Validate toàn bộ trước khi ghi định nghĩa/masks. Lỗi rebuild không được để lại
  định nghĩa đã ghi một nửa hoặc metadata sai; phục hồi trạng thái nhất quán.
- Một lần tạo là một bước undo. Overlap một phần hoặc toàn bộ được phép: mỗi dòng
  có UUID riêng nhưng union proxy chỉ chứa một bản mỗi Source vertex/edge.
- Tạo đường trên vùng đang DANP Form-hidden giữ nguyên masks, không tự Reveal.
- Hide/Reveal/xóa trong Edit Mode cũng giữ object/mode khi object đó còn tồn tại.
  Khi rebuild proxy đang edit, khôi phục selection bằng Source IDs của phần còn
  hiệu lực, không dùng proxy indices cũ.

## 3. Danh sách control là công cụ quản lý selection

Mỗi dòng đại diện một định nghĩa người dùng tạo: tên có thể đổi, trạng thái,
**Select**, **Hide/Reveal**, **Delete**. Định danh lệnh là Source UUID + control UUID,
không phải tên hoặc vị trí dòng. Đổi tên chỉ đổi nhãn, không đổi network revision
hay masks. Tên mặc định không bị tái sử dụng gây nhầm sau khi xóa.

Click dòng chỉ chọn dòng quản lý, không ngầm đổi mode hay bật đường. Nút Select:

| Context | Hành vi Select |
| --- | --- |
| Source Edit Mode | Chọn đúng vertex/edge của định nghĩa trên Source, giữ Edit Mode |
| Controller Edit Mode | Chọn phần effective tương ứng trên proxy, giữ Edit Mode |
| Object Mode | Nút ghi rõ Edit Source & Select; vào Source Edit Mode và chọn định nghĩa |

Select mặc định thay selection trong mesh đang thao tác; tùy chọn Add to Selection
cho phép gom nhiều dòng. Không cần thêm hệ thống group hay multi-owner control.
Định nghĩa hidden vẫn chọn được trên Source để kiểm tra; trên proxy chỉ chọn phần
effective. Nếu phần đó rỗng, báo đường đang ẩn, không tự Reveal.

**Trạng thái dòng là kết quả hình học, không phải cờ on/off độc lập:**

- On: toàn bộ hình học định nghĩa đang effective.
- Partial: chỉ một phần đang effective.
- Hidden: không còn phần effective của định nghĩa.

Hiện số cạnh/điểm đang bật so với tổng khi cần giải thích Partial. Với Partial, hành
động chính là Reveal Whole; menu dòng vẫn có Hide Whole. Không dùng checkbox nhị
phân khiến người dùng hiểu nhầm mỗi dòng sở hữu trạng thái riêng.

Hide Whole dùng edge intent cho các thành phần có cạnh, node intent cho các thành
phần điểm độc lập. Một định nghĩa vừa có cạnh vừa có điểm rời phải giữ cả hai ý
định, không bỏ điểm rời chỉ vì danh sách edge không rỗng. Hide Selected cũng phân
biệt node intent với endpoint flags khi chọn cạnh. Reveal tuân canonical masks.

Ví dụ A chứa cạnh 1–2, 2–3; B chứa 2–3, 3–4:

- Hide A làm cạnh 2–3 ẩn chung; B hiển thị Partial nếu 3–4 còn bật. Vertex 3 còn
  được cạnh 3–4 hỗ trợ. Tooltip nói rõ thao tác ảnh hưởng phần trùng của dòng khác.
- Xóa A giữ cạnh 2–3, 3–4 của B; giữ masks trên phần còn định nghĩa. Chỉ xóa hình
  học proxy không còn được định nghĩa nào dùng, và prune masks tương ứng.
- Xóa B cuối cùng làm proxy rỗng; Source vẫn giữ nguyên mọi vertex, edge, face và
  tọa độ. Controller rỗng vẫn có thể nhận đường mới.

Delete từng dòng có undo; không cần hộp xác nhận cho từng lần xóa. Remove Controller
là thao tác khác, đặt trong Maintenance và ghi rõ định nghĩa Source vẫn được giữ.

# Module boundaries

The add-on is being split without changing the Source/Controller contract or
the `dan_form.*` operator IDs.  Persistent Source data remains authoritative;
runtime caches and transaction buffers are disposable.

## Current extraction boundary

- `constants.py` owns storage keys, attribute names and extension identifiers.
- `runtime.py` owns process-local caches, guards, transaction handles and
  callback state.  It never becomes a second geometry store.
- `storage.py` owns JSON-backed control definitions, masks and Source UUID
  helpers.  It does not calculate patches or write viewport UI state.
- `core/controls.py` owns pure effective-control and mask resolution over
  persistent IDs.
- `core/patches.py` owns pure face-graph partitioning; Blender code only adapts
  Mesh/BMesh data into face records and caches the returned runtime result.
- `core/graph.py` and `core/proportional.py` own the replaceable graph-distance
  and attenuation candidates used by the existing deformation facade.
- `blender/context.py` resolves the active Source/controller pair without
  trusting stale scene pointers.
- `blender/proxy.py` owns controller rebuild, Source-to-proxy sync and topology
  recovery. It receives mapping/selection functions through `ProxyDeps` rather
  than importing the facade.
- `blender/workflows.py` owns deformation transactions, mask mutation and
  Source writeback. It receives mesh/proxy/UI-independent callbacks through
  `WorkflowDeps`.
- `registration.py` owns Blender class/property/handler/keymap registration;
  `blender/lifecycle.py` owns depsgraph/load/undo/redo callbacks and runtime
  invalidation. The root facade only passes itself as the compatibility API
  object.
- `operators.py` owns Blender operators, picking helpers, UIList and sidebar
  classes. Its `bind()` hook injects facade adapters only after package import.
- `ui/overlay.py` owns viewport drawing and display-only patch batches. It has
  the same bind boundary and never changes Source geometry.
- `__init__.py` remains a small compatibility facade while the remaining Blender
  adapters, core geometry and UI modules are extracted incrementally. Lifecycle
  callbacks are no longer defined in the facade.

Existing scripts and live regression checks can continue to use the old private
facade names during the migration. New modules must import runtime state through
the runtime module so assignments cannot silently diverge from the shared state.

## Target boundary

`core` will receive IDs, connectivity, masks, coordinates and targets rather
than Blender objects. `blender` will adapt Mesh/BMesh, Source storage, proxy
sync and context. Operators and UI will only resolve user input and present
results. Agent and human commands will enter the same workflow primitives.

The extension package has `__init__.py` at its root, so packaging copies the
complete contents of the source package beside it. This is required for relative
imports and for future `core`, `blender`, `operators` and `ui` subpackages.

## Compatibility rules

Persistent keys, Source IDs, operator IDs, controller parenting and undo-visible
behavior stay unchanged during extraction. A refactor is accepted only when the
static suite, package contents and the existing open-Blender regression workflow
remain usable. Numerical interpolation changes are a separate task.

# ADR-011 — Patch ownership uses control transforms

**Status:** Accepted for the deformation upgrade, 2026-09-19

## Decision

An enabled Source patch is controlled by the enabled control definitions incident
to its boundary. A patch with one incident control receives that control's
operation transform over its full captured scope. A patch with multiple incident
controls blends their transforms within the patch. Selected controls provide
their absolute transform from Operation Rest; enabled unselected controls provide
the identity transform and are hard stationary constraints. Hidden controls are
not incident controls.

The canonical operation representation is shared by Blender UI and agents:
operation type, pivot, coordinate space, absolute targets and proportional
settings. A target mapping may represent an arbitrary free deformation, but it
must not silently change the ownership rules above.

## Consequences

- Translation, rotation and scale use the same patch-local ownership semantics.
- A single control no longer loses rotation or scale through averaging its
  boundary displacement vectors.
- Names, list order and logical grouping remain selection/storage conveniences;
  the effective Source IDs and patch incidence determine geometry.
- Patches outside the captured incident scope remain unchanged and are never
  written back.
- Evaluated modifier bleed is measured separately from the Source-base contract;
  a modifier-aware boundary policy requires separate evidence.

The transform fit is a replaceable numerical candidate. It must pass the exact
target, stationary-boundary, scope, cancel and parity gates before release.

Trong lúc transform, các thao tác sửa định nghĩa, mắt, Sync, H/Alt-H và dựng lại proxy bị khóa với thông báo ngắn; không âm thầm đổi selection hoặc Source.

## 4. Dữ liệu lưu và mạng hiệu dụng

Source giữ persistent ID của vertex/edge và một schema có phiên bản. Mỗi `ControlDefinition` lưu `uuid`, tên, tập vertex/edge ID, `enabled`, và tập ID ẩn một phần **trong chính định nghĩa đó**. Không lưu tọa độ control. UIList active row và selection là trạng thái tương tác, không là nguồn hình học.

```
effective_edges = hợp cạnh đang bật của mọi định nghĩa
effective_vertices = các đầu mút effective_edges
                   ∪ các điểm đứng riêng đang bật
```

Một node ẩn trong một định nghĩa làm các cạnh của định nghĩa đó tại node mất hiệu lực; định nghĩa khác vẫn có thể giữ node/cạnh ấy. Hiding toàn bộ mục không xóa partial masks; Reveal dùng tọa độ Source mới. Xóa mục bỏ record rồi tính lại hợp tập, không can thiệp mesh Source. Dựng lại proxy chỉ dùng Source ID, Source tọa độ và mạng hiệu dụng; selection cũ được giữ theo giao các ID còn tồn tại. Không giữ pose proxy cũ như nguồn tọa độ thay thế.

### Di chuyển dữ liệu cũ

Schema hiện tại dùng mask vertex/edge chung trên Source. Khi nâng schema:

1. Đọc file cũ một lần, kiểm tra ID và topology trước khi chuyển.
2. Chiếu mỗi ID đang bị mask chung vào mọi định nghĩa chứa ID đó. Nhờ vậy trạng thái nhìn thấy ngay sau mở file vẫn giống bản cũ, kể cả phần trùng.
3. Tạo `enabled` và partial masks theo từng định nghĩa; kiểm tra mạng hiệu dụng trước/sau migration bằng ID.
4. Lưu schema mới chỉ sau khi qua kiểm tra. Nếu lỗi, không sửa Source; báo lỗi kèm ID để phục hồi.
5. Runtime chỉ dùng schema mới. Adapter migration được cô lập; không duy trì hai luồng solver, hai loại mask hoặc fallback âm thầm.

Thử migration trên **bản sao** `.blend`, gồm file hiện tại có 26 định nghĩa và phần hình học trùng. Không ghi đè bản autosave hoặc dữ liệu đang dirty của người dùng trong quá trình phát triển.

## 5. Core: selection, patch và biến dạng

### Selection

Selection chuẩn là tập Source ID lấy từ Controller Edit BMesh. Click/Pick của DANP lọc theo bề mặt Source khi X-Ray tắt; Box Select, Circle và Lasso giữ quy tắc native của Blender đối với geometry Controller. Giữ thao tác Shift thêm, Ctrl bỏ, góc nhìn perspective/orthographic và vertex/edge mode của Blender.

### Patch

Tính các thành phần mặt liên thông khi không đi xuyên qua effective control edges. Đường hở không tách mặt thì không được giả tạo patch mới. `S` và `U` là điều kiện biên trong các patch liên quan; chúng không tạo thêm loại control hay trọng số theo tên. Scope chụp ở đầu thao tác là hợp patch chạm `S`; không ghi ra ngoài scope.

### Solver

Đầu vào thuần dữ liệu: topology/patch, `P0`, `S`, `U`, target tuyệt đối `Q`, proportional settings. Đầu ra: tọa độ mới theo Source ID trong scope và thống kê. Ràng buộc cứng: `output[S]=Q`, `output[U]=P0[U]`, ngoài scope không đổi; no-op trả `P0` chính xác. Junction chung được giải một lần theo Source ID.

Trước tiên đo và giữ output của solver hiện tại với các fixture một điểm, nhiều điểm, vòng, hai vùng rời nhau, junction, G/R/S và patch có một/nhiều biên. Chỉ sửa phần phụ thuộc số lượng/định nghĩa `control_uuid` bằng thay đổi nhỏ nhất đáp ứng bất biến I4; kiểm tra kết quả với fixture thêm mục trùng. Nếu việc tách khỏi định nghĩa không thể thực hiện mà vẫn giữ chất lượng, lúc đó thử ứng viên transform field từ **nhóm liên thông hình học của selection trên mạng hiệu dụng**. Solver nằm sau cùng một hợp đồng dữ liệu để có thể thay mà không đổi UI/transaction; không mở rộng solver chỉ vì muốn tái cấu trúc mã.

Proportional chỉ tác động lên vertex tự do trong patch, một lần. `Radius = 0` trước mắt giữ hành vi toàn patch hiện dùng. Các profile/radius khác có bảng so sánh hình dạng và hiệu năng trước khi quyết định mặc định cuối.

## 6. Một chủ sở hữu cho G/R/S và Undo

Trạng thái tối thiểu: `IDLE → ACTIVE → COMMITTED` hoặc `IDLE → ACTIVE → CANCELLED`. Một Source chỉ có một phiên ACTIVE. Đầu phiên chụp Source UUID, topology/network/proxy generation, object transform, `P0`, `S/U`, scope và proxy selection. Không tạo P0 mới giữa các preview.

Mỗi sự kiện kéo đọc target tuyệt đối của `S`, kiểm tra finite/ID/generation, giải từ P0 và ghi preview Source. Controller lúc đang kéo là input tạm; sau confirm/cancel nó đồng bộ từ Source. Confirm/cancel lấy từ sự kiện của chính transform đang chạy. Lỗi trước ghi không đổi Source; lỗi có preview hợp lệ nhưng phải hủy thì phục hồi P0. Đổi mode/selection/định nghĩa giữa phiên bị chặn hoặc kết thúc phiên tường minh.

Trước khi viết lại, làm một thử nghiệm nhỏ trên Blender 5.1/5.2 để chọn **một** cơ chế sở hữu native G/R/S có thể bắt đúng Begin, Confirm, Cancel và một bước Undo. Có thể dùng macro/wrapper nếu thử nghiệm chứng minh đủ các sự kiện; không giữ observer và macro song song. Bỏ timeout 20 lần kiểm tra để commit, cờ `had_delta` suy từ tập target sai, và bản ghi undo runtime chỉ chứa một thao tác mỗi Source.

Undo/Redo nhiều bước phải khôi phục Source, định nghĩa/visibility, selection có thể khôi phục, proxy và overlay đúng thứ tự. Sau `undo_post`/`redo_post`, chỉ đánh dấu cache cũ vô hiệu và chạy resync trong context an toàn; không ghi edit BMesh bên trong handler. Lưu/mở file phải dựng lại proxy/caches từ Source, không lưu transaction runtime.

## 7. Đồng bộ và overlay

- Source Edit/Object coordinate change: đánh dấu tọa độ đã đổi; proxy cập nhật từ Source trong context an toàn. Object transform của Source được áp qua parenting/matrix đúng một lần.
- Proxy Edit ngoài phiên hợp lệ: không ghi ngược Source; resync hoặc báo lỗi. Trong phiên hợp lệ, chỉ `S` sinh target ngược.
- Overlay: lấy ID và tọa độ từ Source; đối với modifier/cage, dùng hình học hiển thị được đánh giá từ Source với mapping được kiểm tra. Nếu mapping không đáng tin, dùng fallback có cảnh báo thay vì vẽ một đường có vẻ chính xác nhưng lệch mesh.
- Cache partition chỉ phụ thuộc topology và mạng hiệu dụng. Cache vị trí/GPU phụ thuộc Source geometry, object transform, modifier và mode/selection phù hợp. Source edit, confirm/cancel, hide/reveal, undo/redo, load, duplicate và rebuild đều vô hiệu đúng cache rồi yêu cầu redraw.
- Draw callback chỉ vẽ; depsgraph handler chỉ phát hiện/đánh dấu thay đổi. Không chạy solver hay sửa geometry bên trong callback vẽ.

## 8. Ranh giới mã sau nâng cấp

```
model/          schema, ID, định nghĩa, migration, validation
core/network/   hợp membership, effective edges/vertices, patch topology
core/solve/     P0 + S/U/Q + patch -> tọa độ Source mới
blender/mesh/   đọc/ghi Mesh và Edit BMesh theo persistent ID
blender/proxy/  dựng và đồng bộ controller từ Source
interaction/    selection, depth policy, phiên G/R/S, Undo
ui/             sidebar hiện tại, overlay, thông báo trạng thái
agent/          chuyển lệnh thành cùng selection/target/operation
```

Đây là ranh giới trách nhiệm, không bắt buộc tạo đúng từng thư mục như sơ đồ. Dọn `operators.py` lớn thành nhóm chức năng; bỏ `bind(api)` sao chép toàn bộ tên private của facade, alias runtime dư, hai đường biến dạng và các nhánh compatibility chỉ còn phục vụ mã cũ. Các ngưỡng số, pixel tolerance và đơn vị radius phải có tên, lý do và test; không nhánh theo tên nhân vật/scene/control.

## 10. Ma trận kiểm thử bắt buộc

1. **Tập hợp/overlap:** A và B trùng node, trùng cạnh, giao nhau; ẩn A, xóa A, bật lại, partial H; phần B giữ không đổi.
2. **Tính độc lập danh sách:** đổi tên/thứ tự, tách một mục thành hai mục, thêm mục trùng; cùng mạng/S/U/Q cho cùng output.
3. **G/R/S nối tiếp:** G → LMB → chọn vùng khác → R/S/G ngay, không cần chờ; vùng trước không reset. Lặp với chọn từ list, click và Box Select.
4. **Cancel:** Esc/RMB trước và sau preview; Source/proxy về P0/C0, không tạo bước Undo có nghĩa.
5. **Undo/Redo:** ít nhất ba biến dạng liên tiếp, hide/reveal xen giữa, trở đi và trở lại từng bước; overlay/proxy khớp sau mỗi bước.
6. **Selection/X-Ray:** vertex trước/sau cùng vùng màn hình, perspective/orthographic, Box Select native trên loose Controller, Shift/Ctrl, vertex/edge mode; click/Pick kiểm tra Source occlusion.
7. **Source trực tiếp:** edit vertex Source ở Edit Mode, object transform, mode switch, save/reopen; proxy và overlay theo Source.
8. **Solver:** một vertex, span, loop, hai vùng chọn rời nhau, junction, patch một/nhiều biên, open chain, target no-op, radius đổi, ngoài scope giữ nguyên.
9. **Lỗi và dữ liệu:** topology đổi giữa phiên, ID thiếu/trùng, duplicate Source, hai Source cùng scene, xóa proxy và dựng lại, migration file cũ; lỗi chặn trước ghi.
10. **Agent parity và hiệu năng:** cùng target cho cùng Source output qua UI/agent; đo toàn bộ đường preview trên file thật 1698 Source vertex/264 proxy vertex và fixture lớn hơn.

Static tests hiện tại chỉ là kiểm tra bước đầu; các bài thử live phải xác nhận tọa độ theo ID, không chỉ chụp ảnh. Mỗi chặng có báo cáo Blender version, fixture, expected/actual, thay đổi file, PASS/FAIL/NOT RUN và lỗi còn lại.

## 11. Định nghĩa hoàn thành

Bản nâng cấp chỉ được coi là xong khi người dùng làm liên tục từ tạo control → chọn bằng click/box/list → G/R/S → hide/reveal/delete → sửa Source trực tiếp → Undo/Redo → save/reopen mà Source, proxy và overlay luôn khớp theo các bất biến trên; test live và migration qua; chất lượng patch mặc định không thoái lui; runtime chỉ còn một schema, một đường transform và một đường solver được dùng thật.

# Source và Controller: đồng bộ Modifier

## Quy tắc sở hữu

Source vẫn là nguồn hình học duy nhất. Controller là proxy vertex/edge có thể
dựng lại; nó không lưu một bản mesh thứ hai và không được dùng để khôi phục
Source sau khi modifier thay đổi.

Khi Source có modifier phù hợp với proxy, DANP sao chép modifier đó sang
Controller theo cùng thứ tự và thiết lập. Đây là bản sao được DANP đồng bộ,
không phải một liên kết datablock của Blender. `Ctrl-L > Copy Modifiers` của
Blender chỉ sao chép một lần; nó không cập nhật Controller khi Source đổi.

## Chính sách proxy

Controller không có mặt. Vì vậy không phải modifier nào của Source cũng có
nghĩa trên Controller. Phiên bản hiện tại chỉ cho phép `MIRROR`, gồm trục,
Mirror Object, Merge, Merge Distance và Clipping. `SUBSURF` và các modifier
cần mặt bị bỏ qua trên Controller nhưng vẫn giữ nguyên trên Source.

Mục tiêu của Mirror trên Controller là để Edit Mode native của Blender áp dụng
đúng Merge/Clipping tại mặt phẳng đối xứng. Mirror chỉ mở rộng phần hiển thị và
không tạo persistent ID mới; các vertex được chọn vẫn là vertex gốc của nửa
mesh Source.

## Đồng bộ vòng đời

```text
Init/Rebuild Controller
        │
        ├─ dựng vertex/edge proxy từ Source IDs
        └─ copy các modifier được cho phép

depsgraph thấy Source modifier đổi
        │
        └─ so sánh chữ ký RNA đầy đủ → đồng bộ Controller

Undo/Redo hoặc mở file
        │
        └─ dựng lại modifier Controller từ Source trước khi tiếp tục runtime
```

Chữ ký modifier bao gồm tên, loại, cờ hiển thị và các thuộc tính RNA của
modifier, nên đổi Clipping, Merge Distance, trục hoặc Mirror Object đều làm
Controller được cập nhật. Việc đồng bộ không chạy solver và không ghi tọa độ
Source.

`is_active` chỉ cho biết modifier nào đang được chọn trong giao diện của từng
object. Giá trị này không được sao chép hoặc so sánh: Source có thể đang chọn
Subdivision trong khi Mirror là modifier duy nhất của Controller. Một lần
đồng bộ không có thay đổi hình học phải giữ nguyên chính modifier Controller
và Edit Mode đang hoạt động.

## Ràng buộc đường giữa

Mirror trên Controller xử lý transform native trong Edit Mode. Phần DANP ghi
preview về Source phải tiếp tục tôn trọng mặt phẳng Mirror khi Clipping bật;
đây là lớp kiểm tra riêng của phép biến dạng, vì modifier của Controller không
thể tự bảo vệ một lần ghi tọa độ trực tiếp vào Source.

Writeback hiện áp dụng quy tắc này theo hệ tọa độ của Mirror: vertex vốn nằm
trên mặt phẳng được giữ ở mặt phẳng, vertex ngoài mặt phẳng không được vượt qua
trục khi Clipping bật, và vertex đi vào Merge Distance được snap về mặt phẳng
khi Merge bật.

Nếu test thực tế cho thấy patch ở đường giữa vẫn bị xem như đường hở, bước tiếp
theo là bổ sung đồ thị đối xứng ảo trong phép tính patch. Không tạo control
trái/phải và không Apply Mirror trong bước này.
